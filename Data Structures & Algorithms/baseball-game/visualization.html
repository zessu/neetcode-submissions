Baseball Game

LeetCode 682 — Simulate a score record with a stack

Array Stack Simulation O(n) O(n) space

Problem Overview

You start with an empty record. Process each operation in order:

  • A number x: add x to the record.
  • "+": add the sum of the last two valid scores.
  • "D": add double the last valid score.
  • "C": remove (invalidate) the last valid score.

Return the sum of all scores left in the record.

Input: operations = ["5","2","C","D","+"] Output: 30 Record evolution: [5] -> [5,2] -> [5] -> [5,10] -> [5,10,15] Sum: 5 + 10 + 15 = 30
Key observation: every operation touches only the most recent scores, and "C" is an undo of the last score. That is precisely a stack.

Approach 1: Stack Simulation (Implemented)

Intuition: Push numbers, peek at the top one or two for "D"/"+", and pop for "C". No element other than the top is ever read or removed.

The stack grows on the right and shrinks from the right. Nothing below the top ever moves.

for (const op of operations) { if (!isNaN(parseInt(op))) record.push(parseInt(op)); else if (op === "+") record.push(record.at(-1) + record.at(-2)); else if (op === "D") record.push(record.at(-1) * 2); else if (op === "C") record.pop(); } return record.reduce((a, b) => a + b, 0);

Why summing at the end is important

A "C" can remove a score after it has already contributed to a running total. Keeping the record and summing once at the end avoids having to subtract on every pop.

Approach 3: Brute-Force Replay

Intuition: To know the record after operation i, replay operations 0..i from an empty record. This recomputes the same state many times, but it is an easy correctness baseline.

Common Pitfalls

  • Rejecting negative scores. A digits-only test fails on "-2". Use parseInt or Number.
  • Popping while evaluating "+". Read the top two values and push their sum; the operands stay.
  • Summing too early. A later "C" can invalidate an already-counted score; sum at the end.
  • Treating "C" as a reset. It removes only the single most recent valid score.
  • Doubling the wrong value. "D" uses the current top after all prior pops, not a value from the original input.
  • Forgetting operator parsing order. Check for a numeric operation before the switch; all three operators parse to NaN.
