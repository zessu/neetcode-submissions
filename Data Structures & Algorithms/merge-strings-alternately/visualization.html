Merge Strings Alternately

LeetCode 1768 — Interleave two strings starting with word1

String Two Pointers Simulation

Problem Overview

Take characters in turns: word1[0], then word2[0], then word1[1], and so on. When one string is exhausted, append the untouched remainder of the other string and stop.

Input: word1 = "abc", word2 = "pqr" Output: "apbqcr" word1: a b c word2: p q r merged: a p b q c r

Approach 1: Shrink Both Strings Each Iteration (Implemented)

Intuition: simulate the definition with two working copies. Append the front character of each, then cut those characters off. If one copy is empty, dump the rest of the other copy and break.

Approach 2: Index Two Pointers (Optimal)

Intuition: use a single index i over both strings. At each step, emit word1[i] if it exists and word2[i] if it exists. No strings are ever sliced or copied.

The length guards i < word1.length / i < word2.length are what replace the "append the remainder" special case. Missing a guard would push undefined.

Approach 3: Recursive Merge

Intuition: read the definition recursively — the answer is the first character of each string, followed by the merge of the two suffixes. When one suffix is empty, the other suffix is the answer.

Time: O(L1 + L2) Space: O(L1 + L2) stack
Call chain for merge("ab", "pqrs")
merge("ab", "pqrs") → "a" + "p" + merge("b", "qrs")
merge("b", "qrs") → "b" + "q" + merge("", "rs")
merge("", "rs") → base case: word1 empty → "rs"
unwind: "b" + "q" + "rs" = "bqrs"
unwind: "a" + "p" + "bqrs" = "apbqrs"

The base case must return the whole remaining string, not a single character. Returning word2[0] would silently drop the tail.

Recursion depth equals min(L1, L2) + 1. Each call consumes one character from both strings, so the chain stops as soon as the shorter string is exhausted — not at the longer length. A base case that only checks one string would be wrong.

Approach Comparison

Approach Time Space Slicing? Notes
Shrink via slice (implemented) O(L1+L2) O(L1+L2) Yes, every iteration Direct simulation; explicit remainder handling
Index two pointers O(L1+L2) O(L1+L2) output No Guaranteed linear; no intermediates
Recursive merge O(L1+L2) O(L1+L2) stack Yes Elegant but stack-bound

With a copying engine, the slice-based and recursive versions degrade to O(L1² + L2²); the index version never does. At the stated limit of 100 characters per string, all three are effectively instant.

Common Pitfalls

  1. Dropping the tail. When the lengths differ, the leftover characters must be appended in order — once, at the end.
  2. Reading past the end. word2[i] for an out-of-range i is undefined; concatenating it produces the literal text "undefined". Guard every index.
  3. Looping only min(L1, L2) times without a remainder step — the longer string's tail disappears.
  4. Using continue instead of break after appending the remainder: the other string is still non-empty, so the loop repeats and duplicates the tail forever.
  5. Starting with word2. The first emitted character is always word1[0], regardless of which string is longer.
  6. Assuming the inputs were mutated. Strings are immutable; word1 = word1.slice(1) only rebinds the local parameter.
  7. Unicode assumptions. slice(0,1) and word[i] split UTF-16 surrogate pairs. Safe for the lowercase-only constraint, not for arbitrary text.
