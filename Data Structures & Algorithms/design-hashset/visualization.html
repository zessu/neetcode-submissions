Design HashSet

LeetCode 705 — add / contains / remove with no built-in hash table

Hash Table Design Array Linked List Hash Function

Problem Overview

Implement a set of integers supporting add(key), contains(key), and remove(key). Duplicate adds are no-ops, removing an absent key does nothing, and keys lie in [0, 10^6] with at most 10^4 calls.

Input: ["MyHashSet","add","add","contains","contains","add","contains","remove","contains"] [[], [1], [2], [1], [3], [2], [2], [2], [2]] Output: [null, null, null, true, false, null, true, null, false]

A set has no values — only "present" or "absent" — so each operation is a membership decision.

Approach 1: Array + Linear Scan (Implemented)

Intuition: Keep the distinct keys in an array. Every operation scans the array with includes; insertion appends, deletion filters.

This guard is what makes the structure a set rather than a bag; without it, duplicates would accumulate and inflate every later scan.

Common Pitfalls

  • Duplicate adds: check membership before inserting, or the "set" becomes a multiset.
  • Removing an absent key: return early (or guard index !== -1); an unguarded splice(-1, 1) deletes the wrong element.
  • Truthiness on key 0: if (key) treats a valid key as missing. Compare with === instead.
  • Forgetting to reassign: filter returns a new array; this.values = this.values.filter(...) is required.
  • Sentinel collisions: -1 from indexOf is not a valid index — check it before using the result.
