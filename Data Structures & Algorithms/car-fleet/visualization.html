Car Fleet

LeetCode 853 — Count car fleets arriving at destination

Array Sorting Stack

Problem Overview

N cars travel on a one-lane road toward a target. Faster cars catch up to slower ones and form fleets. Return the number of distinct fleets that arrive.

Input: target = 12, position = [10, 8, 0, 5, 3], speed = [2, 4, 1, 1, 3] Output: 3

Approach 1: Max-Time Tracking (Iterative)

Intuition: Calculate each car's arrival time. Sort by position descending. If a car behind takes longer than the fleet ahead, it forms a new fleet.

Time: O(N log N) Space: O(N)
Cars on the road (target = 12)

Step 1: Calculate arrival times
Pos 10, Spd 2 → (12-10)/2 = 1.0
Pos 8, Spd 4 → (12-8)/4 = 1.0
Pos 5, Spd 1 → (12-5)/1 = 7.0
Pos 3, Spd 3 → (12-3)/3 = 3.0
Pos 0, Spd 1 → (12-0)/1 = 12.0
Step 2: Sort by position descending, then count fleets
Pos 10, t=1.0 → 1.0 > 0 → Fleet 1, maxTime=1.0
Pos 8, t=1.0 → 1.0 ≤ 1.0 → joins fleet
Pos 5, t=7.0 → 7.0 > 1.0 → Fleet 2, maxTime=7.0
Pos 3, t=3.0 → 3.0 ≤ 7.0 → joins fleet
Pos 0, t=12.0 → 12.0 > 7.0 → Fleet 3, maxTime=12.0
Result: 3 Fleets

Cars at pos 10, 8
Fleet 2 (t=7.0)
Cars at pos 5, 3
Fleet 3 (t=12.0)
Car at pos 0
  1. Pair each position with its time to target: (target - pos) / speed
  2. Sort pairs by position descending (closest to target first)
  3. Initialize fleets = 0, maxTime = 0
  4. If current car's time > maxTime, increment fleets and update maxTime

Approach 2: Monotonic Stack

Intuition: Same time calculations, but use a stack. Push arrival time if it's greater than the top (can't catch up). Stack size = number of fleets.

Time: O(N log N) Space: O(N)
Stack operations (sorted by position desc)
t=1.0 → Stack: [1.0] Push (stack empty)
t=1.0 → Stack: [1.0] Skip (1.0 ≤ 1.0)
t=7.0 → Stack: [1.0, 7.0] Push (7.0 > 1.0)
t=3.0 → Stack: [1.0, 7.0] Skip (3.0 ≤ 7.0)
t=12.0 → Stack: [1.0, 7.0, 12.0] Push (12.0 > 7.0)

Stack size = 3 = number of fleets

Approach Comparison

Approach Time Space Pros Cons
Max-Time Tracking O(N log N) O(N) Simple, efficient (just a variable) Requires sorting
Monotonic Stack O(N log N) O(N) Intuitive for dependent problems Slightly more overhead
