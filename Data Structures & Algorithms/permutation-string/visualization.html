Permutation in String

LeetCode 567

String Sliding Window Hash Table Two Pointers

Problem Overview

Given two strings s1 and s2, return true if s2 contains a permutation of s1 as a substring.

Input: s1 = "ab", s2 = "eidbaooo" Output: true Explanation: s2 contains "ba", which is a permutation of "ab".

Approach 1: Brute Force

O(|s1|! · |s2|)

Generate every permutation of s1 and check if any is a substring of s2.

Time: O(|s1|! · |s2|) Space: O(|s1| · |s1|!)

Unusable for |s1| ≥ 8.

Approach 2: Sliding Window with Rebuilt Counts

O(|s1| · |s2|)

Slide a fixed-size window of length |s1| across s2. At each position, rebuild a 26-element frequency count and compare against s1's count.

Time: O(|s1| · |s2|) Space: O(1) (fixed 26 arrays)

const arr1 = Array.from({ length: 26 }).fill(0); for (let i = 0; i < s1.length; i++) { arr1[s1.charCodeAt(i) - 97]++; } let start = 0, end = start + s1.length; while (end <= s2.length) { const arr2 = Array.from({ length: 26 }).fill(0); for (let i = 0; i < s1.length; i++) { arr2[s2.charCodeAt(start + i) - 97]++; } if (arr1.every((v, i) => v === arr2[i])) return true; start++; end = start + s1.length; } return false;

Approach 3: Sliding Window with Rolling Updates

Optimal — O(|s2|)

Maintain the window count incrementally. On each slide, decrement the leaving character and increment the entering character. Track a matches counter across all 26 buckets.

Time: O(|s1| + |s2|) Space: O(1)

Rolling Update Concept

Char leaving
window[out]--
→
Slide +1
O(1) per step
→
Char entering
window[in]++

Only 2 indices change per slide. Update matches for those 2 buckets only.

When matches === 26, all frequency buckets match → permutation found.

Approach Comparison

Approach Time Space Pros Cons
Brute Force O(|s1|! · |s2|) O(|s1| · |s1|!) Easiest to describe Unusable for |s1| ≥ 8
Sliding + Rebuild O(|s1| · |s2|) O(1) Clear, easy to follow Repeated work per slide
Sliding + Rolling O(|s1| + |s2|) O(1) Strictly linear, no wasted work More bookkeeping for matches
