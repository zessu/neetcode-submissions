Binary Tree Right Side View

LeetCode 199 — the rightmost node at every depth

Tree BFS DFS Binary Tree

Problem Overview

Standing to the right of the tree, return the values you can see from top to bottom. That is the rightmost existing node at each depth — not a chain of right-child pointers, because a left child becomes visible when its level has nothing further right.

Input: root = [1, 2, 3, null, 5, null, 4] 1 / \ 2 3 \ \ 5 4 Depth 0: [1] -> 1 Depth 1: [2, 3] -> 3 Depth 2: [5, 4] -> 4 Output: [1, 3, 4]

Approach 1: Brute Force — Scan Once per Depth

Intuition: Compute the height, then for each depth do a full left-to-right walk and remember the last node seen at that depth.

Time: O(n · h) Space: O(h)
One full tree scan per visible level
depth 0 1 → scan all nodes, keep last at depth 0 = 1
depth 1 23 → rescan, keep last at depth 1 = 3
depth 2 54 → rescan, keep last at depth 2 = 4

A tree with height h is walked h times, so this is O(n · h) — correct but wasteful.

Approach 2: BFS Level Order

Intuition: Process the tree one level at a time. Dequeue exactly the nodes currently in the queue; the last one dequeued is the rightmost node of that level.

Time: O(n) Space: O(w)
Queue contents at the start of each level
level 0 1 → last = 1; enqueue 2, 3
level 1 23 → last = 3; enqueue 5, 4
level 2 54 → last = 4; no children
view = [1, 3, 4]

The queue holds at most the widest level w; no per-level arrays are retained.

Approach 3: DFS Left-to-Right, Collect Every Level (Implemented)

Intuition: Group nodes by depth in a 2D array while traversing left first. Each level is filled left-to-right, so its last entry is the rightmost node. Extract it with map.

Time: O(n) Space: O(n)
Preorder visits and the level buckets they fill
level 0 1 last = 1
level 1 23 last = 3
level 2 54 last = 4
map(last) = [1, 3, 4]

The 2D array stores all five values, although only three are needed. That is the O(n) space trade-off.

Approach 4: DFS Right-First, First Visit Wins

Intuition: Visit the right child before the left. The first node reached at a new depth is necessarily the rightmost node at that depth, so record it and never overwrite.

Time: O(n) Space: O(h)
Visit order 1 → 3 → 4 → 2 → 5; first visit per depth is the answer
First at its depth → visible
Depth already recorded
function dfs(node, depth) { if (!node) return; if (depth === result.length) result.push(node.val); // first visit dfs(node.right, depth + 1); dfs(node.left, depth + 1); }

Approach Comparison

Approach Time Space Pros Cons
Brute Force (per depth) O(n · h) O(h) Easy to reason about Re-walks the tree h times
BFS Level Order O(n) O(w) Direct definition; no full-tree storage Queue can hold a wide level
DFS Left-to-Right, collect all (implemented) O(n) O(n) Clean grouping; easy to switch to left view Stores every node value
DFS Right-First O(n) O(h) One value per level, optimal memory Must get right-before-left order correct

Key Insight & Common Pitfalls

Key insight: the view is one node per depth — the rightmost one that exists. A left child is visible whenever its level has nothing to its right (see [1,2,3,4,null,null,null,5], where 4 and 5 are visible).
Pitfall: following right-child pointers and stopping at null gives the wrong answer; you must consider every level.
Pitfall: taking the first node in a left-to-right traversal gives the left side view. Either take the last of each level, or traverse right-first and take the first.
Pitfall: in BFS, snapshot the queue length before processing a level; otherwise levels blur together.
Pitfall: the implemented version keeps every node value (O(n)), not just one per level. For huge trees, prefer BFS or right-first DFS.
