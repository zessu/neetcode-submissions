Valid Palindrome II

LeetCode 680 — Palindrome after at most one deletion

Two Pointers String Greedy O(1) Space

Problem Overview

Return true if s can become a palindrome by deleting at most one character. Zero deletions count, so an already-palindromic string is valid.

Input: s = "abca" Output: true delete 'b' -> "aca", or delete 'c' -> "aba" Input: s = "abc" Output: false deleting any one character still leaves a non-palindrome

Approach 1: Brute Force (Try Every Deletion)

Intuition: Remove each character in turn and check whether the result is a palindrome. Also check the original string, because deleting zero characters is allowed.

Efficiency note: the submitted version reverses the two sliced strings on every mismatch and does not return false when both fail. That is correct but can reach O(n²). Returning false immediately after both candidates fail, or using an index helper, restores O(n).

For a longer remainder, the helper simply walks its two indices inward, using O(1) memory.

function validPalindrome(s) { let l = 0, r = s.length - 1; while (l < r) { if (s[l] !== s[r]) { return isPal(s, l + 1, r) || isPal(s, l, r - 1); } l++; r--; } return true; } function isPal(s, l, r) { while (l < r) { if (s[l] !== s[r]) return false; l++; r--; } return true; }

Approach 4: Recursive Deletion

Intuition: Walk inward with a budget of one deletion. At a mismatch, spend the budget on either the left or the right character and recurse. The string is valid if either branch reaches the center.

Time: O(n) Space: O(n) call stack

At most two branches are explored because the budget is consumed after the first skip. Recursion depth can reach n / 2, which is risky at n = 10^5.

Key Insights & Pitfalls

Key insight: at the first mismatch, only two deletions can possibly work — remove the left character or remove the right character. Everything outside the mismatched pair has already matched, so deleting an inner character cannot repair the pair.
Pitfall 1: Zero deletions are allowed. Check the original string first; "aba" must return true.
Pitfall 2: Test both candidates. Checking only the left or only the right misses valid cases like "abca".
Pitfall 3: After a deletion, the rest must be an exact palindrome — do not allow a second skip in the helper.
Pitfall 4: Slice indices are easy to get wrong: deleting left is s.slice(0,left) + s.slice(left+1); the helper equivalent is the range [left+1, right].
Pitfall 5: If both candidates fail at the first mismatch, return false right away. Continuing is correct but can turn O(n) into O(n²).
