Binary Tree Postorder Traversal

LeetCode 145 — left → right → node

Tree DFS Stack Binary Tree

Problem Overview

Return the values of a binary tree in postorder: fully visit the left subtree, then the right subtree, then the node itself. The root is therefore always the last value in the output.

Input: root = [1, null, 2, 3] 1 \ 2 / 3 Output: [3, 2, 1] 3 is a leaf -> 2's left is done, right is empty -> 1

Approach 1: Recursive DFS (Implemented)

Intuition: The definition is already recursive. Recurse left, recurse right, then record the node.

Time: O(n) Space: O(h)
Visit order on root = [1, null, 2, 3]
Already output
Output next
Waiting on children
Call order (depth-first, output happens on the way back up)
traverse(1)→ left = null→ traverse(2)→ traverse(3)
emit 3→ emit 2→ emit 1→ [3, 2, 1]

Each node is appended only after both recursive calls return. The output is built entirely on the unwinding phase.

Approach 2: Two Stacks (Reverse of Root-Right-Left)

Intuition: Postorder left, right, node reversed is node, right, left. Generate that with a normal stack, collecting nodes into a second stack, then drain the second stack to reverse it.

Time: O(n) Space: O(n)
stack1 = work list, stack2 = collected output (reversed later)
start 1 s2 empty
pop 1 2 s2 1 push 1 to s2; left is null, push right child 2 to s1.
pop 2 3 s2 12 push 2 to s2; push its left child 3 to s1.
pop 3 empty s2 123 3 has no children; s1 is now empty.
drain s2 back-to-front→ 3 → 2 → 1

Push left before right into s1, so right is processed first. This is the easiest iterative version to remember.

Approach 3: One Stack + lastVisited

Intuition: Simulate the call stack. Descend left as far as possible; then either move into an unvisited right subtree, or emit the node when both subtrees are finished. lastVisited distinguishes "right subtree not done" from "right subtree just finished".

Time: O(n) Space: O(h)
State trace for root = [1, null, 2, 3]
step 1 1 Descend left from 1: push 1, curr becomes null. Top 1 has right child 2, and lastVisited is null ⇒ move curr to 2.
step 2 12 Push 2, descend to 3 and push it. Top 3 has no right child ⇒ emit 3 and pop; the stack is shown after that pop. lastVisited = 3.
step 3 12 Top 2 has no right child ⇒ emit 2 and pop. lastVisited = 2.
step 4 1 Top 1: right is 2, but lastVisited === 2, so the right subtree is done ⇒ emit 1 and pop.
result = [3, 2, 1]
while (curr || stack.length) { while (curr) { stack.push(curr); curr = curr.left; } const node = stack[stack.length - 1]; if (node.right && lastVisited !== node.right) { curr = node.right; } else { result.push(node.val); lastVisited = stack.pop(); } }

Approach 4: Morris Traversal (O(1) Space)

Intuition: Attach a dummy node whose left child is the root. Thread the rightmost node of each left subtree back to its ancestor. When a thread is found, the left subtree's right spine is finished, so output that spine in reverse. The dummy's spine produces the final right boundary.

Time: O(n) Space: O(1)
Threads for root = [1, null, 2, 3]
Nodes on the reversed right spines
Temporary thread
  1. Thread 2.right = dummy, then descend to 1. Node 1 has no left child, so move right to 2.
  2. Thread 3.right = 2, then descend to 3. Node 3 has no left child; follow its thread back to 2.
  3. At 2, the thread 3.right === 2 is found: output the reverse of the spine 3 → 3, remove the thread, then move right to the dummy.
  4. At the dummy, the thread 2.right === dummy is found: output the reverse of the spine 1 → 2 → 2, 1, then stop.
output = [3, 2, 1]

Approach Comparison

Approach Time Space Pros Cons
Recursive DFS (implemented) O(n) O(h) Three lines; exactly mirrors the definition Call-stack overflow on very deep trees
Two Stacks O(n) O(n) Simple iterative logic Stores every node a second time
One Stack + lastVisited O(n) O(h) Iterative with optimal stack space Subtle right-child condition
Morris Traversal O(n) O(1) No auxiliary memory at all Temporarily rewires pointers; complex

Key Insight & Common Pitfalls

Key insight: reverse(postorder) = node, right, left. Reversing a root-right-left walk is the shortest correct iterative recipe.
Pitfall: the two-stack loop must push left before right. LIFO then pops right first, which is required for the reverse order.
Pitfall: in the one-stack version, checking only node.right !== null loops forever once the right subtree has been emitted. Compare with lastVisited too.
Pitfall: the root is the last output, not the first. If the first value equals the root, you have written preorder.
Pitfall: the submission stores res on the instance. Reusing one Solution object for multiple calls would append to old results.
