Remove Duplicates from Sorted Array

LeetCode 26 — Compact the unique values into the first k cells

Array Two Pointers In-Place

Problem Overview

Because nums is sorted, duplicates are adjacent. Overwrite the front of the array with one copy of each distinct value, in order, and return how many there are. Everything after index k - 1 is ignored.

Input: nums = [0,0,1,1,1,2,2,3,3,4] Output: k = 5, nums = [0,1,2,3,4,_,_,_,_,_] ^ checked ^ ignored (any values) Only nums[0..k-1] is validated — the tail may keep stale duplicates.

Approach Time Space In place? Notes
Set + sort + copy (implemented) O(n log n) O(n) Yes (writes back) Short; sorts data that is already sorted
Read/write pointers O(n) O(1) Yes Optimal; exploits adjacency of duplicates
New array + copy back O(n) O(n) Yes (writes back) Clear one-pass dedupe; allocates
Repeated splice O(n²) O(1) Yes Quadratic shifting; easy to skip elements

Common Pitfalls

  1. Returning the array. The answer is k; the judge reads the mutated nums separately.
  2. Forgetting to write back. A deduplicated copy that never touches nums fails the in-place check.
  3. Clearing the tail. Unnecessary. Only nums[0..k-1] is verified; stale values are fine.
  4. Lexicographic sort. If you sort, pass (a, b) => a - b; the default compares strings and misorders negatives and multi-digit values.
  5. Incrementing after splice. The next element shifts into the current index, so the loop must re-check the same position.
  6. Comparing the wrong neighbor. With two pointers, compare against nums[write - 1] (last kept) or nums[read - 1] (previous input) — both work on sorted input; mixing them does not.
  7. Starting write at 0. Index 0 is always unique; starting at 0 and comparing to nums[-1] is undefined and quietly writes wrong values.
  8. Assuming the array shrinks. JavaScript keeps the original length; k is a logical prefix boundary.
