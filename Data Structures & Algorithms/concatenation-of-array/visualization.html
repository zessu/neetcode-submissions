Concatenation of Array

LeetCode 1929 — Return two copies of the array back to back

Array Simulation O(n) O(n) space

Problem Overview

Given nums of length n, build ans of length 2n such that ans[i] = nums[i] and ans[i + n] = nums[i]. In short: concatenate nums with itself.

Input: nums = [1,2,1] Output: [1,2,1,1,2,1] Input: nums = [1,3,2,1] Output: [1,3,2,1,1,3,2,1]
Key insight: the output is two copies, not an array of two arrays. The second copy begins exactly at index n.

Approach 1: Spread / Concatenation (Implemented)

Intuition: Spread each copy of nums into a new array literal. The first spread fills the first half, the second spread fills the second half.

Best / implemented Time: O(n) Space: O(n)
Two spreads, one result — nums = [1,2,1]
[...nums]
10 21 12
+
10 21 12
→
result
10 21 12 13 24 15
First copy (indices 0..n-1)
Second copy (indices n..2n-1)

The new array has length 2n = 6. The original nums is untouched.

return [...nums, ...nums];

Approach 2: Preallocate and Fill Both Positions

Intuition: Allocate the final 2n slots, then send each input element to two destinations: its own index and its index plus n.

Time: O(n) Space: O(n)
Each input cell feeds two output cells

One pass over the input, two writes per element. The purple arrows are the first copy; the green arrows are the second.

Approach 3: Two-Pass Append

Intuition: Read through the input twice and append each value to the result. Pass 1 builds the first half; pass 2 appends the identical second half.

Time: O(n) Space: O(n)
Result slots filled pass by pass — nums = [1,3,2,1]
Pass 1i = 0..n-1
10 31 22 13 ·4 ·5 ·6 ·7
Pass 2i = 0..n-1 again
10 31 22 13 14 35 26 17

The second pass writes indices n..2n-1; the values are the same because the loop restarts at index 0.

Approach 4: Modulo Mapping (Earlier Submission)

Intuition: For each output index i in [0, 2n), the value is nums[i % n]. The modulo wraps the second half back to the start of the input.

Time: O(n) Space: O(n)
Index mapping for nums = [1,2,1] (n = 3)
Output index i 0 1 2 3 4 5
i % n 0 1 2 0 1 2
nums[i % n] 1 2 1 1 2 1

The first three indices use i directly; indices 3..5 wrap to 0..2. This is the logic used by submission-0.ts and submission-1.ts before the spread rewrite.

Approach Comparison

Approach Time Space Pros Cons
Spread / Concatenation (implemented) O(n) O(n) One line; no index math; readable Less explicit about the two halves
Preallocate + Fill O(n) O(n) Single pass, exact index control Manual allocation of 2n slots
Two-Pass Append O(n) O(n) Mirrors the definition; no modulo Two loops; dynamic growth
Modulo Mapping O(n) O(n) One formula for all indices; generalizes to k copies Modulo per element; easier to mis-size

Common Pitfalls

  • [nums, nums] is wrong. It creates a nested array with two elements; use [...nums, ...nums].
  • Result length must be 2n. Writing the second copy at i + n requires room for exactly twice the input.
  • Do not mutate the input. nums.push(...nums) changes the caller's array and can make the loop length change mid-flight.
  • A single pass only fills half. Either spread twice, run the loop twice, or write both positions in one pass.
  • Sparse arrays and map. new Array(2 * n).map(...) skips holes; use Array.from or an explicit loop.
  • Modulo divisor is n, not 2n. The wrap must return to the start of nums.
