Climbing Stairs

LeetCode 70 — Count the ways to climb n steps using 1-step and 2-step moves

Dynamic Programming Memoization Fibonacci

Problem Overview

You can climb 1 or 2 steps at a time. Return the number of distinct sequences of moves that reach the top of an n-step staircase. Order matters, so 1 + 2 and 2 + 1 are different ways.

Input: n = 2 Output: 2 // 1+1, 2 Input: n = 3 Output: 3 // 1+1+1, 1+2, 2+1 Input: n = 5 Output: 8 // the 6th Fibonacci number

The key observation: to stand on step n, your last move came from step n - 1 or step n - 2. Those two cases are disjoint, so their counts add.

The number of ways to reach each step — 1, 1, 2, 3, 5, 8 — is the Fibonacci sequence.

Approach 1: Brute-Force Recursion

Intuition: Recurse on the two possible last moves without remembering anything. ways(n) = ways(n-1) + ways(n-2).

Time: O(2n) Space: O(n)

The green nodes (3 and 2) are solved more than once. As n grows, the number of duplicate calls grows exponentially.

Approach 2: Memoized DFS (Implemented)

Intuition: Cache the answer for each step count. Once recurr(3) is known, every branch that needs it reads the cache in O(1).

Time: O(n) Space: O(n)

current call solved and cached base case
const cache = new Map(); const recurr = (val) => { if (val === 0) return 1; if (val < 0) return 0; if (cache.has(val)) return cache.get(val); const left = recurr(val - 1); const right = recurr(val - 2); cache.set(val, left + right); return left + right; }; return recurr(n);

Every state from 0 to n is solved exactly once. With n = 5, the cache ends up holding {1:1, 2:2, 3:3, 4:5, 5:8}, and the total work is linear instead of exponential.

Approach 3: Bottom-Up DP

Intuition: Build the table from the bottom of the staircase. dp[i] is the number of ways to reach step i, and it depends only on dp[i-1] and dp[i-2].

Time: O(n) Space: O(n)
dp[i] = ways to reach step i

At i = 5: dp[4] + dp[3] = 5 + 3 = 8. The base value dp[0] = 1 means "one way to stand still."

dp[0] = 1; for (let i = 1; i <= n; i++) { dp[i] = (dp[i - 1] || 0) + (dp[i - 2] || 0); } return dp[n];

No recursion, so the stack cannot overflow. The tradeoff is that all n + 1 entries are stored even though only the last two are ever read.

Approach 4: Two-Variable DP (Constant Space)

Intuition: Keep only the previous two values and roll them forward. This is the same recurrence with O(1) memory.

Time: O(n) Space: O(1)

let prev = 0, curr = 1; for (let i = 0; i < n; i++) { [prev, curr] = [curr, prev + curr]; } return curr;

This is the version most interviewers expect after you describe the recurrence: linear time, constant space, no stack.

Approach 5: Matrix Exponentiation

Intuition: The recurrence is linear, so it can be written as a matrix power. Exponentiation by squaring computes it in logarithmic time.
