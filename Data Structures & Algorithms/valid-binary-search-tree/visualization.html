Valid Binary Search Tree

LeetCode 98 — Every node must respect the bounds of all its ancestors

Tree DFS BST Recursion

Problem Overview

A binary tree is a valid BST only if, for every node, all keys in its left subtree are strictly smaller and all keys in its right subtree are strictly greater. Checking a node against its immediate children is not enough — the constraint comes from the whole ancestor chain.

Input: root = [2,1,3] Output: true Input: root = [5,1,4,null,null,3,6] Output: false (4 is a right child of 5, but 4 < 5) Input: root = [5,4,6,null,null,3,7] Output: false (3 is locally below 6, but it lies in the right subtree of 5)

Approach 1: Brute Force — Scan Subtrees at Every Node

Intuition: Translate the definition directly. For every node, find the maximum of its left subtree and the minimum of its right subtree, then recurse.

Time: O(n²) worst Space: O(h)
Tree [10,5,15,3,7,null,20] — the same nodes are scanned repeatedly

Shaded boxes = subtrees scanned to validate the root

validate(10): scan 5,3,7 and 15,20 → validate(5): scan 3,7 again → validate(15): scan 20 again
Node 3 and node 7 are re-checked at every ancestor → O(n²) for a skewed tree

Approach 2: Bounds Propagation DFS (Implemented)

Intuition: Carry the allowed open interval down the recursion. Every node must satisfy min < node.val < max; going left lowers the upper bound, going right raises the lower bound.

Time: O(n) Space: O(h)
Example 2 with inherited intervals — node 4 is impossible before its subtree is touched
isValid(5, -∞, ∞) → pass → isValid(1, -∞, 5) → pass → isValid(4, 5, ∞) → false

Because the check happens before recursing, the failure at 4 short-circuits the whole right branch. Nodes 3 and 6 are never examined.

Why Example 3 needs the inherited bound

Node 3 is inside (5, 6), not merely below 6
  1. Call isValid(root, -Infinity, Infinity).
  2. If the node is null, return true.
  3. If node.val <= min or node.val >= max, return false.
  4. Left child inherits (min, node.val).
  5. Right child inherits (node.val, max).
  6. Return the && of both recursive results.
isValid(root, min, max) { if (root === null) return true; if (root.val > min && root.val < max) { return isValid(root.left, min, root.val) && isValid(root.right, root.val, max); } return false; }

Approach 3: In-Order Traversal

Intuition: A valid BST's in-order traversal is strictly increasing. Walk left → node → right and compare each value with the previous one.

Time: O(n) Space: O(n) or O(h)

Approach 4: Morris In-Order Traversal (O(1) Space)

Intuition: Thread each node's in-order predecessor back to it, so the traversal can return to an ancestor without a stack. Remove the thread when it is used.

Time: O(n) Space: O(1)
Threading the predecessor of 5 (node 4) before descending left

No left child for 4 → visit 4, follow the thread to 5

while (cur) { if (!cur.left) { visit(cur); cur = cur.right; } else { pre = cur.left; while (pre.right && pre.right !== cur) pre = pre.right; if (!pre.right) { pre.right = cur; // thread cur = cur.left; } else { pre.right = null; // unthread visit(cur); cur = cur.right; } } }

Each edge is walked at most twice, so the time stays O(n). The tree is restored before the traversal finishes. This is the only approach with O(1) auxiliary space.

Approach Comparison

Approach Time Space Pros Cons
Brute force scans O(n²) worst O(h) Literal definition; easy to reason about Re-scans subtrees; slow on skewed trees
Bounds DFS (implemented) O(n) O(h) One pass; early rejection; no extra data structures Must thread the bounds correctly
In-order traversal O(n) O(n) / O(h) Simple "sorted order" invariant Must reach the leftmost node before checking; array costs memory
Morris traversal O(n) O(1) Constant extra space; no recursion Temporarily rewires pointers; subtle to implement

Key Insights & Common Pitfalls

One sentence: a node is valid only if it lies strictly inside the intersection of all ancestor constraints — that intersection is exactly the open interval passed down the recursion.
  • Do not check only parent and child. In [5,4,6,null,null,3,7], every parent-child pair is ordered correctly, yet 3 is in the right subtree of 5.
  • Use strict inequalities. Duplicates are invalid, so the guard is min < val && val < max.
  • Carry both bounds. A left child keeps the lower bound and takes the parent as its upper bound; a right child keeps the upper bound and takes the parent as its lower bound.
  • Do not use 0 or -1 as "no bound". Negative node values are legal; use -Infinity / Infinity.
  • Empty trees are valid. Return true for null; the LeetCode constraints guarantee at least one node, but the base case still matters for leaves.
  • Recursion depth can reach 104. A skewed tree can exhaust the JS stack; Morris or an explicit stack avoids that.
