Balanced Binary Tree

LeetCode 110 — Does every node's left and right subtree differ in height by at most 1?

Easy Tree Depth-First Search Binary Tree

Problem Overview

A tree is height-balanced when, for every node, the heights of its left and right subtrees differ by at most 1. Heights are counted in nodes: an empty subtree has height 0, a leaf has height 1.

The challenge is that balance is defined locally but depends on heights computed from the bottom up. A balanced root does not guarantee balanced subtrees, so the condition must be checked at every node.

Input: root = [3,9,20,null,null,15,7] Output: true Input: root = [1,2,2,3,3,null,null,4,4] Output: false (root's left subtree has height 3, right has height 1)

Approach 1: Brute Force (Height at Every Node)

Intuition: Translate the definition directly. For each node, call a separate height() helper on both children, compare the results, then recurse into the children.

Time: O(n²) worst Space: O(h)
The same subtrees are measured again and again
isBalanced(3): height(9)=1, height(20)=2 → diff 1
isBalanced(9): height(null)=0, height(null)=0 → diff 0
isBalanced(20): height(15)=1, height(7)=1 → diff 0
height(15) and height(7) are recomputed by the root's check after node 20 already measured them

On a skewed tree the repeated work grows quadratically: each of the n nodes walks an ever-shrinking chain.

  1. Define height(node): return 0 for null, otherwise 1 + max of child heights.
  2. For every node, compute the left and right heights independently.
  3. Fail if their absolute difference exceeds 1.
  4. Recurse into both children and combine the results.

Approach 2: Post-order DFS with a Flag (Implemented)

Intuition: Compute each subtree's height once. Since the children must be measured before the parent, a post-order traversal naturally checks balance on the way back up. One shared boolean records any failure.

Time: O(n) Space: O(h)
Unbalanced example: [1,2,2,3,3,null,null,4,4]
4 (left): L=0, R=0, diff 0 → return 1
4 (right): L=0, R=0, diff 0 → return 1
3 (left): L=1, R=1, diff 0 → return 2
3 (right): L=0, R=0, diff 0 → return 1
2 (left): L=2, R=1, diff 1 → return 3
2 (right): L=0, R=0, diff 0 → return 1
1: L=3, R=1, diff 2 → balanced = false → return false
Active on the longer path
Node where balance fails
Other nodes
  1. Start with balanced = true.
  2. Recurse left and right; null returns height 0.
  3. If |left - right| > 1, set balanced = false.
  4. Return max(left, right) + 1 so the parent can reuse the height.
  5. After the traversal, return the flag.
let balanced = true; const traverse = (node) => { if (node === null) return 0; const left = traverse(node.left); const right = traverse(node.right); if (Math.abs(left - right) > 1) balanced = false; return Math.max(left, right) + 1; }; traverse(root); return balanced;

Approach 3: Sentinel -1 with Early Exit

Intuition: Let the return value carry the failure. A balanced subtree returns its height; an unbalanced one returns -1. As soon as a parent sees -1 from a child, it can return -1 without inspecting the other child.

Time: O(n) worst Space: O(h)
Early exit: the right subtree (10) is never visited
check(4) → 1
check(3): L=1, R=0, diff 1 → 2
check(2): L=2, R=0, diff 2 → -1
check(1): left = -1 → return -1 immediately → false

Because the left child already reported failure, node 10 is never examined. This is the practical advantage over the flag approach, whose complexity is the same but which always visits the whole tree.

  1. check(null) returns 0.
  2. Compute the left height; if it is -1, return -1.
  3. Compute the right height; if it is -1, return -1.
  4. If the heights differ by more than 1, return -1.
  5. Otherwise return max(left, right) + 1.
  6. The tree is balanced exactly when the final result is not -1.

Approach Comparison

Approach Time Space Early exit? Notes
Brute Force O(n²) worst O(h) No Recomputes subtree heights at every node; easy to derive, too slow for 5000 nodes.
DFS + Flag (implemented) O(n) O(h) No One pass, single shared boolean, simple to read.
Sentinel -1 O(n) worst O(h) Yes Prunes remaining branches after a failure; slightly trickier return contract.
Iterative post-order O(n) O(h) Optional Avoids deep recursion at the cost of an explicit stack.

Key Insights & Common Pitfalls

Key insight: Balance is a bottom-up property. Compute child heights first, then decide at the parent. Returning the height from the same DFS is what turns the quadratic brute force into a linear solution.

  • Only checking the root. Every node must satisfy the condition, including nodes deep inside a subtree.
  • Forgetting the absolute value. Both left - right > 1 and right - left > 1 are failures.
  • Mixing height conventions. This page counts nodes: null = 0, leaf = 1. Be consistent.
  • Stopping without both heights. A parent needs both child heights to judge itself; only a sentinel-based return can safely short-circuit.
  • Empty tree. root = [] is balanced, so the base case must return 0 and the flag must start true.
  • Deep chains. Up to 5000 nodes can mean 5000 stack frames; use an explicit stack if recursion depth is a concern.
