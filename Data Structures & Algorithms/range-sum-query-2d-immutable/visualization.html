Range Sum Query 2D — Immutable

LeetCode 304 — Answer rectangle-sum queries in O(1) after preprocessing

Array Design Matrix Prefix Sum

Problem Overview

The matrix never changes, but sumRegion is called many times. The goal is to precompute once so that each query is constant time. A query covers the inclusive rectangle from (row1, col1) to (row2, col2).

Approach 1: Direct Summation per Query (Implemented)

Intuition: Loop over exactly the cells in the rectangle and add them. No preprocessing; every query pays for the area it covers.

Query: O(m · n) Space: O(1) extra

A full-matrix query visits all 25 cells. Repeated 104 times on a 200 × 200 matrix, that is 4 × 108 additions.

Approach 2: Row Prefix Sums

Intuition: Precompute cumulative sums along each row. A row segment becomes one subtraction, so a query costs one subtraction per row instead of one addition per cell.

Build: O(m · n) Query: O(m)

Only three rows need work, but a query spanning all 200 rows still does 200 subtractions.

Intuition: The transpose of Approach 2: precompute downward cumulative sums and subtract two entries per column.

Approach 4: 2D Prefix Sum (Optimal)

Intuition: Precompute the sum of every top-left rectangle. Then any query rectangle is the sum of four corners, using inclusion–exclusion.

P[5][4] = 38 (bottom-right)

38 − 24 − 14 + 8 = 8

The prefix table has one extra zero row and column, so row2 + 1 and col2 + 1 index the bottom-right corner directly.

Building the table
P[i + 1][j + 1] = matrix[i][j] + P[i][j + 1] // sum above + P[i + 1][j] // sum to the left - P[i][j]; // overlap counted twice query = P[row2 + 1][col2 + 1] - P[row1][col2 + 1] - P[row2 + 1][col1] + P[row1][col1];
P[1][1] = 3 → P[2][2] = matrix[1][1] + P[1][2] + P[2][1] − P[1][1] = 6 + 3 + 8 − 3 = 14

Each cell combines its own value with the prefix above, the prefix to the left, and subtracts the double-counted top-left prefix.

  1. Allocate (m + 1) × (n + 1) zeros.
  2. Fill the table row by row with the recurrence above.
  3. For a query, take the bottom-right prefix.
  4. Subtract the prefix strictly above the rectangle.
  5. Subtract the prefix strictly to the left.
  6. Add back the top-left overlap, then return.

Column prefix sums O(m · n) O(n) O(m · n) Good for narrow column ranges

Key Insights & Common Pitfalls

The core identity: sum(rect) = P[bottom-right] − P[above] − P[left] + P[top-left]. The last term restores the overlap that was subtracted twice.
  • Use padded indices correctly. With a (m+1) × (n+1) table, the bottom-right prefix is P[row2 + 1][col2 + 1], not P[row2][col2].
  • Do not forget the top-left add-back. Omitting + P[row1][col1] subtracts the overlap twice.
  • Rectangle bounds are inclusive. A query from (2, 1) to (4, 3) includes rows 2, 3, and 4.
  • Negative values are legal. Prefix sums still work; do not assume the cumulative values increase.
  • Direct summation is not O(1). It is correct for a few queries, but can time out when sumRegion is called 104 times on a full 200 × 200 matrix.
  • The stored matrix is a reference. The implemented constructor does not copy it; the problem guarantees immutability, so this is safe on LeetCode but not if the caller mutates the array.
