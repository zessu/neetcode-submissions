Same Tree

LeetCode 100 — Compare two trees in lockstep, shape and values

Tree DFS BFS Recursion

Problem Overview

Given roots p and q, decide whether the trees are identical: the same shape, with equal values at every corresponding position. Same values in a different arrangement is not the same tree.

Input: p = [1,2,3], q = [1,2,3] Output: true Input: p = [1,2], q = [1,null,2] Output: false Input: p = [1,2,1], q = [1,1,2] Output: false

Constraints: 0 <= nodes <= 100 in each tree, -10^4 <= Node.val <= 10^4.

Approach 1: Recursive Lockstep DFS Implemented

Intuition: stand on the same position in both trees. Both empty means this branch matches; exactly one empty means the shapes differ; unequal values mean the trees differ. Otherwise the pair matches, and both child pairs must match.

Implemented in this repo Time: O(n) Space: O(h)
Example 1 — every corresponding pair matches, so the trees are identical
(1,1): equal → (2,2) and (3,3): equal → all four null pairs match ⇒ true
isSameTree(p, q): if not p and not q: return true // both empty: match if p and q and p.val == q.val: return isSameTree(p.left, q.left) and isSameTree(p.right, q.right) // both sides must match return false // one null, or values differ

Approach 2: Iterative DFS with a Stack of Pairs

Intuition: the recursive version keeps pending pairs on the call stack. Keep them in an explicit stack instead: push the root pair, then pop, compare, and push matching child pairs. A mismatch is final.

Time: O(n) Space: O(h) average
Stack snapshots for Example 1 (pairs of nodes to compare)
start
[(1,1)]
pop (1,1), push children
[(2,2)]
[(3,3)]
pop (2,2), push nulls
[(null,null)]
[(null,null)]
[(3,3)]
after popping null pairs
[(3,3)]
pop (3,3): equal, push its null children → null pairs are skipped ⇒ stack empties ⇒ true

Null pairs are pushed for uniformity; they are cheap to skip and keep the loop's logic to a single case analysis.

const stack = [[p, q]]; while (stack.length) { const [a, b] = stack.pop(); if (!a && !b) continue; if (!a || !b || a.val !== b.val) return false; stack.push([a.left, b.left]); stack.push([a.right, b.right]); } return true;

Approach 3: BFS with a Queue of Pairs

Intuition: compare level by level. Each queue entry is a pair that must match. BFS rejects a shallow structural difference without first walking to the deepest left leaf.

Time: O(n) Space: O(w)
Queue evolution for Example 2 — mismatch found at depth 1
start (1,1)
pop (1,1) → values equal → enqueue (2,null) and (null,2)
queue (2,null) (null,2)
pop (2,null) → exactly one side is null ⇒ return false immediately

BFS never dequeues (null,2): the first mismatching pair is decisive.

const queue = [[p, q]]; while (queue.length) { const [a, b] = queue.shift(); if (!a && !b) continue; if (!a || !b || a.val !== b.val) return false; queue.push([a.left, b.left]); queue.push([a.right, b.right]); } return true;

Approach Comparison

Approach Time Space Pros Cons
Recursive lockstep DFS (implemented) O(n) O(h) Three cases, mirrors the definition, short-circuits Call-stack depth equals tree height
Iterative DFS + stack O(n) O(h) avg, O(n) worst No recursion limit, early exit Pairs must be pushed and null-pairs skipped manually
BFS + queue O(n) O(w) Finds shallow differences fast Widest frontier can be n/2 pairs

n = nodes in the smaller tree, h = height, w = maximum width.

Common Pitfalls & Key Insights

Comparing values before null checks. Reading p.val when p is null throws. The both-null case must be first.
Using || between the child calls. Both left and right pairs must match; || accepts trees that differ on one side.
Forgetting the value comparison. Checking only "both nodes exist" accepts Example 3, where the shapes match but the children are swapped.
Comparing traversals without null markers. Preorder values of [1,2] and [1,null,2] both start 1,2; missing nulls erase the shape.
Returning false for two empty trees. p = q = [] is a match. A blanket if (!p || !q) return false breaks it.
Key insight: tree equality is a conjunction of three facts — equal roots, equal left subtrees, equal right subtrees. Every approach above is just a different way to enumerate those facts.
Key insight: the pair (a, b) is the unit of work. Both DFS and BFS differ only in the order they process pairs, which is why they share the same three-case check.
