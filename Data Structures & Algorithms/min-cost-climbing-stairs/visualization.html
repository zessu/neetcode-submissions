Min Cost Climbing Stairs

LeetCode 746 — Cheapest route to the top, paying each stair you step on

Dynamic Programming Memoization Array

Problem Overview

cost[i] is the price of stepping on stair i. After paying, you may climb one or two stairs. You may start at index 0 or index 1. Return the minimum total cost to reach the position just past the last index.

Input: cost = [10, 15, 20] Output: 15 // start at index 1, pay 15, jump 2 to the top Input: cost = [1, 100, 1, 1, 1, 100, 1, 1, 100, 1] Output: 6 // pay indices 0, 2, 4, 6, 7, 9 Input: cost = [0, 0, 0] Output: 0

Think of the top as a virtual stair at index n with cost 0. Jumping from n - 2 straight to n means the last real stair is never paid for.

Approach 1: Brute-Force Recursion

Intuition: From stair idx, pay cost[idx] and try both jumps. Keep the cheaper branch. The answer is the cheaper of starting at 0 or 1.

Time: O(2n) Space: O(n)
Every route for cost = [10, 15, 20]
start→ 0 (pay 10)→ 1 (pay 15)→ 2 (pay 20)→ top 45
start→ 0 (pay 10)→ 2 (pay 20)→ top 30
start→ 0 (pay 10)→ 1 (pay 15)→ top 25
start→ 1 (pay 15)→ 2 (pay 20)→ top 35
start→ 1 (pay 15)→ top (jump 2) 15 ✓

The winning route skips stair 2 entirely. Greedily starting at the cheapest stair (10) would lose: it leads to a total of at least 25.

Approach 2: Memoized DFS (Implemented)

Intuition: The remaining cost depends only on the current index. Cache recurr(idx) so each stair is solved once, no matter how many routes reach it.

Time: O(n) Space: O(n)
Memoized states for cost = [10, 15, 20]
recurr(2)20 + min(0, 0)→20
recurr(1)15 + min(20, 0)→15
recurr(0)10 + min(15, 20)→25
answermin(recurr(0), recurr(1))→15
cached result final answer
const cache = new Map(); const recurr = (idx) => { if (idx >= cost.length) return 0; if (cache.has(idx)) return cache.get(idx); const left = cost[idx] + recurr(idx + 1); const right = cost[idx] + recurr(idx + 2); cache.set(idx, Math.min(left, right)); return Math.min(left, right); }; return Math.min(recurr(0), recurr(1));
Why the base case is idx >= cost.length: the top sits one past the array. Once the index passes it, there is nothing left to pay, so the remaining cost is 0. This is also what lets a jump from n - 2 skip the final stair for free.

The answer is min(dp[9] + cost[9], dp[8] + cost[8]) = min(5 + 1, 4 + 100) = 6. The expensive 100 stairs at indices 1, 5, and 8 are never on the optimal route.

dp[0] = 0; dp[1] = 0; for (let i = 2; i <= cost.length; i++) { dp[i] = Math.min( dp[i - 1] + cost[i - 1], dp[i - 2] + cost[i - 2] ); } return dp[cost.length];

No recursion, so the stack cannot overflow, and the table can be printed to debug or to reconstruct the route.

Approach 4: Two Rolling Variables (Constant Space)

Intuition: Only the previous two DP values are needed. Keep them in two variables and update in one pass.

Time: O(n) Space: O(1)
Rolling update for cost = [10, 15, 20], top = 3
iprev = dp[i-2]curr = dp[i-1]New curr = dp[i]
start00—
200min(0 + 15, 0 + 10) = 10

let prev = 0, curr = 0; for (let i = 2; i <= cost.length; i++) { const next = Math.min( curr + cost[i - 1], prev + cost[i - 2] ); prev = curr; curr = next; } return curr;

This is the strongest practical version: linear time, constant memory, and no call stack.
