Reverse String

LeetCode 344 — Reverse a character array in place

Two Pointers String O(1) Space

Problem Overview

Given a character array s, reverse it in place using O(1) extra memory. The function must mutate the caller's array and return nothing.

Input: s = ["h","e","l","l","o"] Output: ["o","l","l","e","h"] Input: s = ["H","a","n","n","a","h"] Output: ["h","a","n","n","a","H"]

Approach 3: Recursive Two Pointers

Intuition: The outer swap is independent of the inner substring. Swap the ends, then recursively reverse what remains between them. The base case is a one-character or empty range.

Time: O(n) Space: O(n) call stack
Call stack for ["h","e","l","l","o"]
reverse(0, 4)  →  swap h/o  →  ["o","e","l","l","h"]
reverse(1, 3)  →  swap e/l  →  ["o","l","l","e","h"]
reverse(2, 2)  →  left ≥ right, return (center)

The stack grows to n / 2 frames. That is fine for short strings, but n = 10^5 can exceed the JavaScript call-stack limit.

Approach 4: Stack-Based Reversal

Intuition: A stack is last-in, first-out. Push every character in order, then pop them back into the array from left to right — the order comes out reversed.

Key Insights & Pitfalls

Key insight: index i and index n - 1 - i are partners. One swap finalizes both, so only floor(n / 2) swaps are needed — the middle element of an odd-length array is already in place.
Pitfall 1: Using while (left <= right) swaps the center with itself. It is harmless but pointless; left < right is the precise condition.
Pitfall 2: Assigning s = s.slice().reverse() only reassigns the local parameter. The caller's array is unchanged, so the judge sees no reversal.
Pitfall 3: Forgetting to increment ptr1 or decrement ptr2 creates an infinite loop.
