Longest Subarray with Sum K

GeeksforGeeks — Find the longest contiguous subarray summing to k

Array Hash Table Prefix Sum Medium

Problem Overview

Given an integer array (positive, negative, or zero values) and a target k, return the length of the longest contiguous subarray whose sum equals k. Return 0 if no such subarray exists.

Input: arr = [10, 5, 2, 7, 1, -10], k = 15 Output: 6 // [10, 5, 2, 7, 1, -10] Input: arr = [-5, 8, -14, 2, 4, 12], k = -5 Output: 5 // [-5, 8, -14, 2, 4] Input: arr = [10, -10, 20, 30], k = 5 Output: 0

Because the array can contain negative numbers, the running sum is not monotonic. That is the key reason a sliding window cannot solve the general problem.

Approach 1: Brute Force

Intuition: Try every start index and extend the end index one element at a time, keeping a running sum.

Time: O(n²) Space: O(1)
arr = [10, 5, 2, 7, 1, -10], k = 15
start 0 10→ 15 ✓ len 2→ 17→ 24→ 25→ 15 ✓ len 6
start 1 5→ 7→ 14→ 15 ✓ len 4→ 5

All O(n²) subarrays are examined. At n = 10⁵, that is roughly five billion operations.

Approach 2: Prefix Sum + Hash Map (Implemented)

Intuition: If the prefix sum up to the current index minus k has been seen before, the elements after that earlier prefix sum to exactly k. Store the first index of every prefix sum to maximize the length.

Time: O(n) Space: O(n)
sum(arr[i..j]) = prefixSum[j] - prefixSum[i - 1] = k
⇒ prefixSum[i - 1] = prefixSum[j] - k

let prefixSum = 0; let maxLength = 0; const diffMap = new Map(); diffMap.set(0, -1); // empty prefix before index 0 for (const [idx, item] of arr.entries()) { prefixSum += item; const diff = prefixSum - k; if (diffMap.has(diff)) { maxLength = Math.max(maxLength, idx - diffMap.get(diff)); } if (!diffMap.has(prefixSum)) { // keep the EARLIEST index diffMap.set(prefixSum, idx); } }

The map stores only the first occurrence of each prefix sum. If a prefix sum appears again later, overwriting it would make future subarrays shorter, never longer.

Approach 3: Sliding Window (Non-Negative Arrays Only)

Intuition: When all values are non-negative, extending the window can only increase the sum and shrinking it can only decrease the sum. A two-pointer window can therefore find the answer in one pass.

Time: O(n) Space: O(1)
Why negatives break it: arr = [10, 5, 2, 7, 1, -10], k = 15
window [10, 5] = 15 → found length 2
extend to [10, 5, 2] = 17 → sum > k, shrink left
[5, 2] = 7 → too small, extend right
[5, 2, 7, 1] = 15 → length 4
[5, 2, 7, 1, -10] = 5 → sum drops; naive logic may discard the prefix

The length-6 answer is [10, 5, 2, 7, 1, -10]. A window that already shrank past index 0 cannot recover it. This is why the hash-map approach is required.
