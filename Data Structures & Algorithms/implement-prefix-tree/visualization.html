Implement Trie (Prefix Tree)

LeetCode 208 — insert, search, and startsWith in O(L)

Trie Design String Hash Table

Problem Overview

Store a set of lowercase words so that both complete-word queries and prefix queries take time proportional to the query length. The trie shares the path of every common prefix.

Input: ["Trie","insert","search","search","startsWith","insert","search"] [[], ["apple"],["apple"],["app"], ["app"], ["app"], ["app"]] Output: [null, null, true, false, true, null, true]

search("app") is false after inserting only "apple" because "app" is a prefix, not a stored word. Inserting "app" later flips the answer to true.

Approach 1: Word List + Linear Scan

Intuition: Keep every inserted word in a list. A query compares against every word, using startsWith for prefix queries.

Time: O(n · L) per query Space: O(n · L)
startsWith("app") scans words = ["apple", "ape", "car"]
"apple" — starts with "app" ✓
"ape" — starts with "ape", not "app" ✗
"car" — no ✗
check word 1 → match, return true

The scan can stop early on a hit, but a miss (e.g. startsWith("b")) inspects every word. Nothing is shared between "apple" and "ape".

Approach 2: Hash Sets of Words and Prefixes

Intuition: Precompute both answers. One set holds complete words (search), another holds every prefix of every inserted word (startsWith).

Time: O(L) query, O(L²) insert Space: O(n · L²) characters
After inserting "apple" and "ape"

words

{ "apple", "ape" }

search("app") → false

prefixes

{ "a", "ap", "app", "appl", "apple", "ape" }

startsWith("app") → true

Every prefix is stored as its own string, so "a", "ap", "app"… are duplicated across words. Queries are a single hash lookup, but insertions pay O(L²) character copying and memory grows with the sum of all prefix lengths.

Approach 3: Object Trie (Implemented)

Intuition: Each node maps a character to a child node. Walking a string is following one property per character; an isWord flag marks where a stored word ends.

Time: O(L) per operation Space: O(T) total characters
Trie after inserting "app", "apple", "ape": paths for search("app") and startsWith("ap")
search("app") → a → p → p exists → isWord = true → true
startsWith("ap") → stops after p → true (marker not needed)

The middle p node is the terminal for "app". Before that insert it only marked the shared prefix "ap", so search("app") was false while startsWith("app") was already true. The insertion flips one flag; no nodes are duplicated.

Path node
Traversed node
Terminal node
class PrefixTree { root = {}; insert(word) { let node = this.root; for (const char of word) { if (!node[char]) node[char] = {}; node = node[char]; } node["isWord"] = true; } search(word) { let node = this.root; for (const char of word) { node = node[char]; if (!node) return false; } return node["isWord"] || false; } startsWith(prefix) { let node = this.root; for (const char of prefix) { node = node[char]; if (!node) return false; } return true; } }

Approach 4: 26-Slot Children Array

Intuition: The alphabet is fixed at 26 lowercase letters, so each node can use a 26-element array instead of an object. Child lookup becomes an index calculation: charCodeAt(i) - 97.

Key Insight & Common Pitfalls

Key insight: a trie stores characters, not words. The path is shared by every word with that prefix, and a single boolean at the end of a path distinguishes a word from a mere prefix.

  • Returning true from search whenever the path exists — that answers startsWith, not search. The terminal flag is mandatory.
  • Marking the wrong node: set isWord after consuming the last character, not on the root or the parent.
  • Overwriting shared children: only create node[char] when it is missing; never replace an existing subtree.
  • Continuing after a missing child: return false immediately; node[char] is undefined.
  • Boolean coercion: an absent flag is undefined; || false (or Boolean()) keeps the return type a real boolean.
