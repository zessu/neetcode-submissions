Construct Binary Tree from Preorder and Inorder Traversal

LeetCode 105 — Rebuild a tree from its two traversal orders

Medium Array Hash Table Divide and Conquer Tree

Problem Overview

Given a preorder traversal (root, left, right) and an inorder traversal (left, root, right) of the same binary tree with unique values, reconstruct and return the tree.

Preorder tells us which value is the root. Inorder tells us which values belong to the left and right subtrees. The whole algorithm is repeated splitting of ranges.

Input: preorder = [3,9,20,15,7] inorder = [9,3,15,20,7] Output: [3,9,20,null,null,15,7] Preorder: root -> left subtree -> right subtree Inorder: left subtree -> root -> right subtree

Approach 1: Recursive Linear Search (Brute Force)

Intuition: The next preorder value is the root. Scan the current inorder range to find it; the values before it form the left subtree, and the values after it form the right subtree.

On a skewed tree, each level scans an almost-full range, so the total work can grow to O(n²).

  1. Keep a pointer to the next preorder value.
  2. For the current inorder range, linearly scan for that value.
  3. Recurse on the left and right sub-ranges.
  4. Return null when the range is empty.

Approach 2: Hash Map + Preorder Pointer (Implemented)

Approach 3: Iterative Construction with a Stack

Intuition: Process preorder left-to-right. The stack holds the path of nodes whose right child is still unresolved. The inorder cursor tells us when the stack top has been fully explored: if the top equals inorder[inIdx], pop it and continue until we find the ancestor that still needs a right child.

The stack follows the current right spine. A node is popped exactly once, so the total work is linear even though the inner while loop looks nested.

  1. Create the root from preorder[0]; push it.
  2. For each remaining preorder value, compare the stack top with inorder[inIdx].
  3. If they differ, attach the new node as the top's left child and push it.
  4. If they match, pop finished nodes, advancing inIdx; attach the new node as the right child of the last popped node.
  5. Return the initial root.

Approach Time Space Notes
Linear search O(n²) worst O(h) + output No extra structure, but scans an inorder range at every node.
Hash map + pointer (implemented) O(n) O(n) O(1) splits, simple recursion, one extra map.
Iterative stack O(n) O(h) + output Avoids recursion depth; harder to get right.
Slicing arrays O(n²) worst O(n²) worst Readable, but copies data at every level.

Key Insights & Common Pitfalls

Key insight: Preorder supplies roots in top-down order; inorder supplies the left/right boundary for each root. With a value-to-index map, every boundary is found in constant time, so the construction is a single linear pass.

  • Taking the wrong preorder value. Each subtree's root is the next unused preorder element, not always preorder[0].
  • Off-by-one ranges. Left is [inLeft, mid-1], right is [mid+1, inRight]; the base case is inLeft > inRight.
  • Searching outside the current range. A global indexOf can return an index from another subtree.
  • Building the right subtree first. The global preorder cursor expects the entire left subtree to be consumed first.
  • Assuming duplicates are allowed. The map approach depends on the unique-value constraint.
  • Deep recursion. A 3000-node chain can overflow the call stack; the iterative version avoids this.
