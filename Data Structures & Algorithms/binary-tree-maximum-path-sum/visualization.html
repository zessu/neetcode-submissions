Binary Tree Maximum Path Sum

LeetCode 124 — Find the best non-empty path, which may bend at any node

Hard Dynamic Programming Tree Depth-First Search Binary Tree

Problem Overview

A path is a sequence of connected nodes with no repeats. It may start and end anywhere, and it may bend at one apex node: going up from one descendant to the apex, then down into the other side. The path must contain at least one node.

The challenge is that the best path may not include the root, and a path that goes up to a parent can use only one of its child branches. Those two facts drive the whole algorithm.

Input: root = [-10,9,20,null,null,15,7] Output: 42 Best path: 15 → 20 → 7 The root -10 is excluded because it would reduce the sum to 34.

Approach 1: Brute Force (Every Node as Apex)

Intuition: Every path has a unique highest node. Try every node as the apex. For each one, compute the best downward gain on the left and on the right, add both to the node's value, and keep the maximum.

Time: O(n²) worst Space: O(h)
The subtree at 20 is measured again when -10 is considered
apex 9: 9apex 15: 15apex 7: 7
apex 20: 15 + 20 + 7 = 42
apex -10: gain(9)=9, gain(20)=35 → 34 → gain(20) was already computed for apex 20

On a skewed tree, each apex walks a long chain, so the total work is O(n²).

  1. Define gain(node) = node.val + max(0, gain(left), gain(right)).
  2. For each node, compute the left and right gains from scratch.
  3. Candidate = node.val + max(0, left) + max(0, right).
  4. Take the maximum candidate over all nodes.

Approach 2: Post-order DFS with a Global Max (Implemented)

Intuition: Compute each node's downward gain once. On the way back up, record the best path that bends at that node using both branches, then return the best single branch to the parent.

Approach 3: Iterative Post-order with a Gain Map

Intuition: Emulate the post-order recursion with an explicit stack. Push each node twice: once to expand its children and once to process it after both gains are known. A map stores the gain of every processed node.

The explicit stack avoids the call-stack limit for deep trees. The map is necessary because a parent needs the gains of children that have already been popped.

  1. Push [root, false].
  2. On the first pop, push [node, true] and its non-null children with false.
  3. On the second pop, read both child gains from the map, clamped to 0.
  4. Update the global best with node.val + left + right.
  5. Store node.val + max(left, right) as this node's gain.
  6. Return the best after the stack empties.

Approach Comparison

Approach Time Space Notes
Brute force O(n²) worst O(h) Try every apex; recomputes the same gains repeatedly.
Post-order DFS (implemented) O(n) O(h) One pass; record both-branch paths, return one-branch gains.
Iterative post-order O(n) O(n) Avoids recursion depth; needs a stack and a gain map.
Two-value recursion O(n) O(h) Returns gain and best path together; no shared mutable state.

Key Insights & Common Pitfalls

Key insight: Record paths that use both branches, but return paths that use one branch. A path cannot branch twice, so the parent may only inherit one side.

  • Assuming the root is included. In Example 2 the best path avoids the root entirely.
  • Returning val + left + right. That is a complete path, not a path that can be extended upward.
  • Ignoring negative branches. Clamp gains with max(0, ...) so a losing subtree contributes nothing.
  • Initializing best to 0. Use -Infinity; a tree of negative values still needs a non-empty path.
  • Resetting the global maximum. Initialize res once, outside the recursion.
  • Deep chains. Up to 30,000 nodes can overflow the JavaScript stack; the iterative version is the safe alternative.
  • Reusing a Solution instance. A class field keeps the previous answer; reset it before a new call if the instance is shared.
