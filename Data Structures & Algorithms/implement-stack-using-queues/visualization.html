Implement Stack using Queues

LeetCode 225 — LIFO behaviour from FIFO queues

Stack Queue Design

Problem Overview

Build push, pop, top, and empty for a LIFO stack using only queue operations (enqueue at the back, dequeue at the front). A queue gives the oldest element first, so either every push or every pop must rotate the queue to bring the newest element to the front.

Input: ["MyStack","push","push","top","pop","empty"] [[], [1], [2], [], [], []] Output: [null, null, null, 2, 2, false]

After two pushes the queue front is 1, but the stack top must be 2. Resolving that mismatch is the entire problem.

Approach 1: Single Array as a Deque (Implemented)

Intuition: Keep the top of the stack at index 0. unshift inserts a new top; shift removes it. The array's front acts like a stack top.

Intuition: Let push be a plain enqueue. To pop, move the first n - 1 elements to the auxiliary queue; the one left at the front is the newest element, i.e. the top.

Common Pitfalls

  • Using push/pop on the array: that is already a stack, not a stack built from queues. The exercise is the emulation itself.
  • Forgetting the swap: after moving elements between two queues, the auxiliary becomes the owner of the data. Without [q1, q2] = [q2, q1], the next operation reads an empty queue.
  • Rotation count: rotate exactly size - 1 times after enqueueing. Rotating size times cancels the work and leaves the new element at the back.
  • top() mutating: peeking must not remove. Read the front, or pop and re-enqueue.
  • Falsy check on empty(): this.elements.length ? false : true is correct here; do not accidentally invert it.
  • Assuming shift is free: it is O(n) for the same reason unshift is — the remaining elements are re-indexed.
