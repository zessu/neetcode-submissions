Longest Common Prefix

LeetCode 14 — Find the shared beginning of every string

String Trie O(S) O(m) space

Problem Overview

Given an array of strings, return the longest string that is a prefix of every string. If they share no starting character, return "".

Input: strs = ["flower","flow","flight"] Output: "fl" Input: strs = ["dog","racecar","car"] Output: "" Input: strs = ["a"] Output: "a"
Key insight: the answer can only shrink as more strings are considered. At the first column where any string disagrees, the prefix is complete.

Approach 1: Vertical Scanning (Implemented)

Intuition: Compare all strings column by column. Column 0 must match everywhere, then column 1, and so on. Stop at the first column that contains a mismatch or a string that has already ended.

Approach 2: Horizontal Scanning

Intuition: Keep a candidate prefix, initially the first string. Compare it with the next string and truncate it until it fits. Repeat. The candidate never grows, so it ends as the longest common prefix.

Approach 3: Sorting

Intuition: After lexicographic sorting, the first and last strings are the "most different" pair. Any prefix shared by those two is shared by everything between them, so only two strings need character-by-character comparison.

Time: O(n log n · L) Space: O(1)–O(n)

Index 2 compares i with o. The common prefix is the first two characters, "fl". The middle string is guaranteed to start with that prefix by sorted order.

Approach 4: Trie

Intuition: Insert all strings into a trie. The common prefix is the path from the root that every word follows. The first node with more than one child (or a word ending) is where the shared path stops.

Time: O(S) Space: O(S)
Trie for ["flower","flow","flight"] — the shared path is f → l

The path is shared for two characters. At depth 3 the trie branches (o vs i), so no third character can be common to every word.

Approach Comparison

Approach Time Space Pros Cons
Vertical Scanning (implemented) O(n · m) / O(S) O(m) Fails fast at the first bad column Rechecks the reference character each column
Horizontal Scanning O(n · m) / O(S) O(1) auxiliary Minimal memory; very short code May rescan a long candidate prefix
Sorting O(n log n · L) O(1)–O(n) (engine-dependent) Only first and last strings need comparison Sorting dominates; reorders input
Trie O(S) O(S) Great for repeated prefix queries High memory for one query

n = number of strings, m = length of the shortest string, L = length of the longest string, S = total characters across all strings.

Common Pitfalls

  • Ignoring shorter strings. A prefix cannot exceed the shortest input; reading past the end gives undefined, which must count as a mismatch.
  • Empty strings. They are allowed by the constraints; any empty string forces the answer to "".
  • Checking only neighboring strings. Pairwise checks can miss a character that fails for a non-adjacent string.
  • Growing the candidate. Horizontal scanning must truncate, never extend, the prefix.
  • Off-by-one slicing. If the mismatch is at index i, return characters 0..i-1, i.e. slice(0, i).
  • Mutating the caller's array. Sorting in place changes the input order; sort a copy if that matters.
