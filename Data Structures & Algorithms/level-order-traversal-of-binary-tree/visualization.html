Binary Tree Level Order Traversal

LeetCode 102 — Collect node values level by level, left to right

Tree BFS DFS Recursion

Problem Overview

Given the root of a binary tree, return its level order traversal: a list where entry i holds every node value at depth i, read left to right. A missing child is not a node and never appears in the output.

Input: root = [3,9,20,null,null,15,7] Output: [[3],[9,20],[15,7]] Input: root = [1] Output: [[1]] Input: root = [] Output: [] // not [[]]

Constraints: 0 <= nodes <= 2000, -1000 <= Node.val <= 1000.

Approach 1: BFS with a Level-Size Loop Optimal

Intuition: a FIFO queue already yields level order. Snapshot the queue length before each round; that many dequeues consume exactly one level, and every child appended during the round belongs to the next level.

Time: O(n) Space: O(w)
Queue state on root = [3,9,20,null,null,15,7]
start3→len = 1, so dequeue one node
round 13value 3 → level 0; append 9 and 20
queue920→len = 2
round 29209 has no children; 20 appends 15 and 7
queue157→len = 2
round 3157no children; queue empty, stop
result[0]3
result[1]920
result[2]157
  1. If root is null, return [].
  2. Initialize queue = [root], result = [].
  3. While the queue is non-empty, snapshot levelSize = queue.length and create level = [].
  4. Dequeue levelSize nodes; push each value into level and enqueue non-null children.
  5. Push level into result.
while (queue.length) { const levelSize = queue.length; // freeze the level boundary const level = []; for (let i = 0; i < levelSize; i++) { const node = queue.shift(); level.push(node.val); if (node.left) queue.push(node.left); if (node.right) queue.push(node.right); } result.push(level); }

Approach 2: Recursive DFS with a Level Index Implemented

Intuition: traversal order and grouping order can be decoupled. Preorder DFS visits every node once and knows its depth from the recursion; write each value straight into result[depth]. Left-before-right recursion keeps each level ordered left to right.

Implemented in this repo Time: O(n) Space: O(h) + output
DFS visit order — the badge shows when each node is written to its level bucket

level 1920

traverse(root, result, level): if root is null: return if result.length === level: result.push([]) // first visit to this depth result[level].push(root.val) traverse(root.left, result, level + 1) traverse(root.right, result, level + 1)

Why result.length === level is the right test

DFS always discovers depth d only after depth d - 1 exists, and it never skips a depth. So when the current level equals the number of buckets already created, this is the first node of a brand-new level. Using if (result[level]) also happens to work because arrays are truthy, but result.length states the invariant directly.

Approach 3: BFS with (node, depth) Pairs

Intuition: carry the depth inside the queue instead of inferring it from level boundaries. Each entry knows exactly which bucket it belongs to, so the outer loop no longer needs to reason about levels at all.

Time: O(n) Space: O(w)
Queue entries carry their own depth label
queue 3 d0 → dequeue 3, write result[0] = [3], enqueue children
queue 9 d1 20 d1 → 9 has no children; write result[1] = [9]
queue 20 d1 15 d2 7 d2 → write result[1] = [9,20]; append 15 and 7 at d2
queue 15 d2 7 d2 → result[2] = [15,7]

The queue can hold entries from two adjacent depths at once, and each entry still routes itself correctly.

const queue = [[root, 0]]; while (queue.length) { const [node, depth] = queue.shift(); if (result.length === depth) result.push([]); result[depth].push(node.val); if (node.left) queue.push([node.left, depth + 1]); if (node.right) queue.push([node.right, depth + 1]); }

Approach Comparison

Approach Time Space (auxiliary) Pros Cons
BFS + level-size loop O(n) O(w) True level order, iterative, no stack risk Must snapshot queue length each round
Recursive DFS + level index (implemented) O(n) O(h) Shortest code, no queue, depth comes free Recursion depth can reach n; less obvious output ordering
BFS + (node, depth) pairs O(n) O(w) Depth is explicit per entry; robust to mixed levels Extra tuple allocation per node

n = number of nodes, h = height, w = maximum width. All three also produce an O(n) output that is not counted as auxiliary space.

Common Pitfalls & Key Insights

Empty tree must return []. A pattern that pushes a level before checking the root yields [[]], which fails Example 3.
Do not re-read queue.length in the loop condition. for (let i = 0; i < queue.length; i++) sees the queue growing and merges levels. Freeze it first.
Append to the level, not the result. In the DFS version, result.push([node.val]) creates one bucket per node; it must be result[level].push(node.val).
One child is not a leaf problem here: a node with only a right child still contributes just itself; do not invent a placeholder for the missing left child in the output.
Key insight: BFS and DFS both run in O(n) — the real difference is auxiliary memory. BFS holds a frontier (width w), DFS holds a path (height h). Choose based on tree shape, not asymptotics.
Key insight: level order is exactly BFS order. Any correct BFS on a tree, with a way to mark level boundaries, produces the answer.
