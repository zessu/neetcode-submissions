Remove Element

LeetCode 27 — Keep every value that is not val in the first k cells

Array Two Pointers In-Place

Problem Overview

Remove all copies of val from nums in place and return how many elements survive. The survivors must occupy nums[0..k-1], but their order may change — the judge sorts that prefix before comparing.

Input: nums = [0,1,2,2,3,0,4,2], val = 2 Output: k = 5 nums[0..4] = [0,1,3,0,4] (any order accepted) nums[5..7] = leftovers, ignored Input: nums = [], val = 0 Output: k = 0

Approach Comparison

Approach Time Space Stable? Notes
Mark + sort + count (implemented) O(n log n) O(1) extra No Sentinel Infinity; sort groups it at the end
Write pointer O(n) O(1) Yes Optimal; handles empty input naturally
Swap with end O(n) O(1) No Fewest writes; must re-check after each swap
Filter + copy back O(n) O(n) Yes Clearest, but allocates

The marking loop is O(n) on V8 because a one-for-one splice does not shift the tail; on an engine that does shift, it degrades to O(n²). The sort is the guaranteed dominant cost.

Common Pitfalls

  1. Deleting instead of replacing. splice(i, 1) shifts the tail and the forward loop skips the element that slides into i. splice(i, 1, Infinity) avoids that.
  2. Returning the array. The answer is k; the judge inspects nums separately.
  3. Wrong sentinel. A value like 0 or -1 can appear in the input. Infinity is safe only because the constraints cap values at 50 — and it sorts last as the string "Infinity".
  4. Assuming numeric order. The default sort is lexicographic, so the survivors are not numerically sorted. That is fine for LeetCode 27 because the prefix is sorted by the judge before comparison.
  5. Empty input. [].reduce(fn) throws a TypeError; the constraints allow an empty array, so guard it or use an initial accumulator.
  6. Advancing after a swap. In the end-swap variant the new value at i has not been checked; incrementing skips it.
  7. Off-by-one on the active range. The range is 0..last inclusive, so the survivor count is last + 1 (0 when everything is removed).
  8. Clearing the tail. Unnecessary; only nums[0..k-1] is validated.
