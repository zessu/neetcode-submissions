Lowest Common Ancestor of a BST

LeetCode 235 — Find the first node where the two search paths split

Tree BST DFS Recursion

Problem Overview

Given a binary search tree and two nodes p and q, return their lowest common ancestor: the deepest node that has both targets as descendants. A node may be a descendant of itself, so if one target equals the current node, that node can be the answer.

Input: root = [6,2,8,0,4,7,9,null,null,3,5], p = 2, q = 8 Output: 6 Input: root = [6,2,8,0,4,7,9,null,null,3,5], p = 2, q = 4 Output: 2 Input: root = [2,1], p = 2, q = 1 Output: 2

Constraints: 2 <= nodes <= 10^5, -10^9 <= Node.val <= 10^9, all values unique, p != q, both targets exist.

Approach 1: BST-Guided Recursive Descent Implemented

Intuition: the BST invariant tells you which side a value lives on. If both targets are smaller than the current node, the answer is in the left subtree; if both are larger, it is in the right. The first node that cannot send both targets to the same side is where their paths diverge — that is the LCA.

Implemented in this repo Time: O(h) Space: O(h)
Example 1 — p = 2, q = 8: the paths 6→2 and 6→8 split immediately at 6
node 6: 2 < 6 < 8 → straddle ⇒ return 6

Only one comparison is needed: the two targets are on opposite sides, so no deeper node can reach both.

lowestCommonAncestor(root, p, q): if root, p, or q is null: return null if p.val < root.val and q.val < root.val: return lowestCommonAncestor(root.left, p, q) if p.val > root.val and q.val > root.val: return lowestCommonAncestor(root.right, p, q) return root // split point, or root is p/q

Why Example 2 returns 2, not 6

p = 2, q = 4 — both targets are left of 6, so descend; then p equals the node
at 6: both < 6 → at 2: p == 2, q = 4 > 2 → return 2

This is exactly why the comparisons must be strict: 2 < 2 is false, so the walk stops instead of searching for a deeper ancestor that cannot exist.

Approach 2: BST-Guided Iterative Walk

Intuition: the recursion is tail-recursive — it never revisits a node on the way back up. A single current pointer reproduces the descent with no call stack at all.

Time: O(h) Space: O(1)
Same rule, pointer instead of stack (p = 3, q = 5)
current = 6
3 < 6 and 5 < 6 → current = 2
3 > 2 and 5 > 2 → current = 4
3 < 4 < 5 ⇒ answer
current.left discarded current.right discarded never touch 0, 3, 5 subtrees

Each step crosses out one whole subtree. The loop runs at most h times and keeps only one pointer.

let current = root; while (current) { if (p.val < current.val && q.val < current.val) current = current.left; else if (p.val > current.val && q.val > current.val) current = current.right; else return current; } return null;
When this wins: a skewed BST with up to 10^5 nodes has height n, and the recursive version can exhaust the JS call stack. The iterative walk has identical time and constant space.

Approach 3: General Binary Tree LCA (Post-Order)

Intuition: ignore ordering and search both subtrees. If the left search and the right search each find one target, the current node is the LCA. If only one side finds something, pass that result upward. This is the LeetCode 236 solution and works on any binary tree.

Time: O(n) Space: O(h)
Post-order results bubble up — p = 3, q = 5 (subtree rooted at 2)
dfs(0) returns null → dfs(4): left returns 3, right returns 5 → node 4 got both sides ⇒ LCA = 4

The result 4 is passed up through 2; node 2 only sees one non-null child, so it is not the LCA. This is correct everywhere, but it explores subtrees the BST ordering would have eliminated — O(n) instead of O(h).

function dfs(node) { if (!node || node === p || node === q) return node; const left = dfs(node.left); const right = dfs(node.right); if (left && right) return node; // one target on each side return left || right; // pass the finding upward }

Approach Comparison

Approach Time Space Pros Cons
BST recursive descent (implemented) O(h) O(h) Three branches, mirrors the split rule, minimal code Stack depth equals tree height
BST iterative walk O(h) O(1) No stack risk, constant space, same comparisons Easy to forget the final null return
General LCA (post-order) O(n) O(h) Works on any binary tree, no BST assumption Visits both subtrees; ignores the ordering that makes this easy

n = number of nodes, h = height (O(log n) balanced, O(n) skewed).

Common Pitfalls & Key Insights

Using <= in the descent tests. Equality means the current node is a target, so it is the LCA. Non-strict comparisons walk past the correct answer (Example 2 breaks).
Assuming p.val < q.val. The inputs are not ordered. Compare both values against the current node, or normalize with min/max.
Solving it as a general tree problem. Searching both subtrees is correct but turns O(h) into O(n) and throws away the BST's entire advantage.
Returning a value instead of a node. The expected return type is TreeNode; returning root.val fails the judge's node comparison.
Key insight: the LCA is the first node where the root-to-p and root-to-q paths diverge. In a BST, "diverge" is detected by comparing both values with the current node.
Key insight: "a node is a descendant of itself" is not a special case to patch — it falls out naturally from returning the current node when one target equals it.
