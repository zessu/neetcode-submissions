Serialize and Deserialize Binary Tree

LeetCode 297 — Encode shape and values, then rebuild them exactly

Tree DFS BFS String Design

Problem Overview

Design serialize to turn a binary tree into a string, and deserialize to rebuild the identical tree from that string. Any encoding is allowed as long as the round trip preserves both structure and values — which means missing children must be recorded somehow.

Input: root = [1,2,3,null,null,4,5] Output: [1,2,3,null,null,4,5] Input: root = [] Output: [] Input: root = [1] Output: [1]

Constraints: 0 <= nodes <= 10^4, -1000 <= Node.val <= 1000.

Approach 1: Preorder DFS with Null Markers Implemented

Intuition: preorder writes a node before its children, so the first token is always the root and each subtree occupies a contiguous range. If every missing child is written as null, the token stream determines the shape uniquely, and decoding is the same traversal in reverse.

Implemented in this repo Serialize: O(n) Space: O(n) + O(h)
Preorder visit order — nodes 1..5 plus the null markers that preserve structure
Serialized tokens (delimiter shown as ·)
1· 2· null· null· 3· 4· null· null· 5· null· null·

2n + 1 = 11 tokens for five nodes. Without the six null tokens, the shape would be lost.

serialize(node): if node is null: return "null_" return node.val + "_" + serialize(node.left) + serialize(node.right) deserialize(tokens): token = tokens.shift() if token is null-marker: return null node = TreeNode(token) node.left = deserialize(tokens) node.right = deserialize(tokens) return node

Decoding is the same recursion in reverse

token 1 "1" → create 1 then build its left subtree first
token 2 "2" → create 2 left of 1
tokens 3-4 "null", "null" → 2 is a leaf
tokens 5-8 "3" → "4" → null, null → 3 gets left child 4
tokens 9-11 "5" → null, null → 3 gets right child 5

Every token is shifted exactly once; the cursor never goes backwards.

Note on the submitted code: it checks if (!parseInt(token)). Since parseInt("0") === 0 is falsy, a real node with value 0 is decoded as null, and "null_" decodes to a node rather than null. The correct test is against the raw marker: token === "null". See SOLUTION.md for details.

Approach 2: BFS Level Order with Null Markers

Intuition: encode the tree the way LeetCode displays it — row by row, with markers for absent children. Decoding pairs children two at a time with the parents in the same queue order.

Time: O(n) Space: O(n) tokens + O(w) queue
Same tree, level by level
level 0 1
level 1 2 3
level 2 N N 4 5
level 3 N N N N

Encoded: 1,2,3,N,N,4,5,N,N,N,N. Decoding: parent 1 takes 2 and 3; parent 2 takes N and N; parent 3 takes 4 and 5; parent 4 takes N and N; parent 5 takes N and N.

serialize(root): if root is null: return "N" queue = [root]; out = [] while queue: node = queue.shift() if node is null: out.push("N") else: out.push(node.val) queue.push(node.left); queue.push(node.right) return out.join(",") deserialize(tokens): if tokens[0] == "N": return null root = TreeNode(tokens[0]) q = [root] i = 1 while q: node = q.shift() leftToken = tokens[i++] // left child slot rightToken = tokens[i++] // right child slot if leftToken != "N": node.left = TreeNode(leftToken); q.push(node.left) if rightToken != "N": node.right = TreeNode(rightToken); q.push(node.right) return root
When this wins: the output is directly comparable to LeetCode's array format, and both directions are iterative, so a 10,000-node skewed tree cannot overflow the call stack.

Approach 3: Nested Parentheses Encoding

Intuition: let the parentheses themselves carry the structure. Each node is written as value(left)(right), with () meaning "empty child". No delimiter or token array is needed — matching parentheses delimit each subtree.

Time: O(n) Space: O(n) string + O(h) stack
Encoding the same tree
1(2()())(3(4()())(5()()))
1 → left group (2()()) right group (3(4()())(5()()))
2 has two empty children 4 and 5 are leaves end of group ⇒ subtree complete

The parser only needs a cursor: read the value, then parse exactly one balanced group for the left child and one for the right. No lookahead or length prefixes.

serialize(node): if node is null: return "()" return node.val + "(" + serialize(node.left) + ")(" + serialize(node.right) + ")"
When this wins: you want a compact, human-readable string with no delimiter collisions. It is also easy to eyeball in a debugger. The trade-off is more parsing code and repeated string allocation.

Approach Comparison

Approach Time Space Pros Cons
Preorder DFS + null markers (implemented) O(n) O(n) string + O(h) stack Encode/decode are mirror images; minimal state Needs a null marker and delimiter; recursion depth
BFS level order + null markers O(n) O(n) tokens + O(w) queue Matches LeetCode format; iterative, no stack risk More markers; queue bookkeeping
Nested parentheses O(n) O(n) string + O(h) stack Self-delimiting, compact, readable Parser is more intricate; many small string allocations

n = nodes, h = height, w = maximum width. The encoded output has Theta(n) size in all three schemes.

Common Pitfalls & Key Insights

Dropping null markers. [1,2] and [1,null,2] both contain 1,2; without markers the decoder must guess the shape and will guess wrong for one of them.
Using value truthiness to detect null. 0 is a legal node value. if (!parseInt(token)) turns a zero node into a missing child — the exact bug present in the submitted implementation.
Leaking the cursor between calls. The index/token array must be created per deserialize call. Instance state that is not reset breaks the second test case.
Empty tree decoding to a node. [] must round-trip to null. new TreeNode(null) is a non-empty tree with an invalid value.
Mismatched traversal orders. Encoding preorder and decoding level order silently produces a different shape; there is no error to catch it.
Preorder + inorder without uniqueness. The classic reconstruction trick requires distinct values. This problem allows duplicates, so it is not a safe general solution.
Key insight: serialization must be a bijection between trees and strings. Null markers are what make the mapping injective — they record the absent branches, not just the present values.
Key insight: the decoder consumes tokens in exactly the order the encoder produced them. Every scheme above is just a different way to make that order self-delimiting.
