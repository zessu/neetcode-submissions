Implement Queue using Stacks

LeetCode 232 — FIFO behaviour from two LIFO stacks

Stack Queue Design

Problem Overview

Build push, pop, peek, and empty for a FIFO queue, using only stack operations (push/pop/peek at the top). A stack removes the newest element; a queue must remove the oldest, so elements have to be reversed exactly once.

Input: ["MyQueue","push","push","peek","pop","empty"] [[], [1], [2], [], [], []] Output: [null, null, null, 1, 1, false]

The front of the queue is the element at the bottom of the push stack. The whole problem is getting access to that bottom element.

Approach 1: Reverse on Every Pop / Peek (Implemented)

Intuition: Pour all but the bottom element into a second stack, which reverses the order. The lone remaining element is the front, so pop it — then pour the second stack back.

Approach 3: One Stack + Recursion

Intuition: Use the call stack as the second stack. Recurse until the bottom element is exposed, remove it, and re-push the held elements while unwinding.

Time: pop/peek O(n) Space: O(n) recursion
pop() on stack = [1, 2, 3] (3 on top)
pop() → hold 3, recurse → hold 2, recurse → stack = [1] → return 1
unwind → push 2 → push 3 → stack = [2, 3]

The held values form the "second stack" implicitly. It works, but recursion depth equals the queue size, and interviewers usually expect explicit stacks.

Approach 4: Two Stacks with Expensive Push

Intuition: Keep the queue permanently reversed, with the front on top, so reads are instant. A new element must go to the bottom; rebuild the stack around it using the second stack.

Common Pitfalls

  • Popping from the wrong end: the queue front is the bottom of arr1, not the top. Popping the top returns the newest element (stack behaviour).
  • Forgetting to pour back: after a pop, arr1 must be restored; otherwise the next push lands in front of the remaining elements.
  • Off-by-one in the loop: while (arr1.length > 1) leaves the front exposed. Using > 0 empties the stack and returns undefined.
  • peek reading the wrong index: after the transfer, arr1 has exactly one element, so read arr1[0], never arr1[arr1.length - 1] of the unreversed array.
  • Checking only one stack with lazy transfer: elements can be split across in and out; empty() must check both.
  • Using shift/unshift: those are not stack operations and bypass the exercise.
