Count Good Nodes in Binary Tree

LeetCode 1448 — no ancestor may be greater

Tree DFS BFS Binary Tree

Problem Overview

A node is good if no node on the path from the root to it has a larger value. Equivalently, the node's value must be greater than or equal to the maximum ancestor value. The root is always good.

Input: root = [3, 1, 4, 3, null, 1, 5] 3 <- good (root) / \ 1 4 <- 1 is not good; 4 is good / / \ 3 1 5 <- 3 is good; 1 is not; 5 is good Output: 4

Approach 1: Brute Force — Scan Every Root Path

Intuition: For each node, materialize the path from the root, take its maximum, and compare. This is the definition translated literally.

Time: O(n · h) Space: O(h)
Path maximum for every node (h = 3, so each path scan costs up to 3)
node 3 3max 3 3 ≥ 3 → good
node 1 31max 3 1 < 3 → not good
node 4 34max 4 4 ≥ 3 → good
node 3 313max 3 3 ≥ 3 → good
node 1 341max 4 1 < 4 → not good
node 5 345max 5 5 ≥ 4 → good

The path is rescanned at every node, giving O(n · h) — on a chain this becomes O(n²).

Approach 2: Recursive DFS Carrying the Max (Implemented)

Intuition: Only the maximum ancestor value matters, so pass it down. Count the node if val >= max, then raise the max and recurse into both children.

Time: O(n) Space: O(h)
Path maximum arriving at each node
Good (val ≥ path max)
Not good (larger ancestor)

Notice the equal case: the leaf 3 sees max 3 and is still good. The comparison must be >=.

Call results, bottom-up
dfs(3 leaf) = 1 → dfs(1 left) = 0 + 1 + 0 = 1
dfs(1 under 4) = 0 → dfs(5) = 1 → dfs(4) = 1 + 0 + 1 = 2
dfs(3 root) = 1 + 1 + 2 = 4
let res = node.val >= maxVal ? 1 : 0; maxVal = Math.max(maxVal, node.val); res += dfs(node.left, maxVal); res += dfs(node.right, maxVal); return res;

Approach 3: BFS with (node, max) Pairs

Intuition: The same state can travel in a queue. Each entry carries a node and the maximum on the path that reached it. No recursion, so deep chains are safe.

Time: O(n) Space: O(w)
Queue contents (node · path max) and the running count
start 3 · 3 count = 0
pop 3 1 · 34 · 3 3 ≥ 3 → count = 1; enqueue children
pop 1 4 · 33 · 3 1 < 3 → count stays 1
pop 4 3 · 31 · 45 · 4 4 ≥ 3 → count = 2
pop 3 1 · 45 · 4 3 ≥ 3 → count = 3
pop 1 5 · 4 1 < 4 → count stays 3
pop 5: 5 ≥ 4 → count = 4

Approach Comparison

Approach Time Space Pros Cons
Brute Force (path scan) O(n · h) O(h) Literal definition O(n²) on a chain
Recursive DFS + max (implemented) O(n) O(h) Optimal time and tight memory Can overflow on a 10^5-node chain
BFS + pairs O(n) O(w) No recursion; safe for deep trees Queue can hold a full level

Key Insight & Common Pitfalls

Key insight: all ancestors collapse into one number — their maximum. Because that number never decreases as you go down, it can be passed by value with no backtracking.
Pitfall: use >=, not >. A node equal to the path maximum is good (the leaf 3 in example 1 depends on this).
Pitfall: compare before updating the max. Updating first makes every node compare equal to itself and returns n.
Pitfall: do not seed the max with 0; values may be negative. Use the root value or -Infinity.
Pitfall: the submission reads root.val without a null check. That is safe under n ≥ 1, but a general helper should guard null.
