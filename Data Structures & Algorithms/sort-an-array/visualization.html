Sort an Array

LeetCode 912 — Sort integers in O(n log n) without built-ins

Array Divide and Conquer Sorting Merge Sort

Problem Overview

Sort nums in ascending order and return it, without calling any built-in sort. Aim for O(n log n) time and minimal extra space.

Input: nums = [5,2,3,1] Output: [1,2,3,5] Input: nums = [5,1,1,2,0,0] Output: [0,0,1,1,2,5]

Intuition: Split the array in half until each piece has one element, then merge sorted pieces pairwise. Merging only ever compares the two front elements, so it is linear.

mergeSort(nums) { if (nums.length < 2) return nums; const mid = Math.floor(nums.length / 2); const left = nums.slice(0, mid); const right = nums.slice(mid); return merge(mergeSort(left), mergeSort(right)); } // merge: repeatedly take the smaller front element
Efficiency note: the submitted merge calls shift(), which is O(length) because it re-indexes the array. Comparisons remain O(n log n), but element movement can reach O(n²). Use i/j index pointers for a true O(n log n) merge.

Approach 3: Quick Sort

Intuition: Pick a pivot and partition: everything smaller goes left, everything larger goes right. The pivot is now final; recurse on both sides.

Time: O(n log n) average, O(n²) worst Space: O(log n) stack

A sorted input with a first-element pivot produces the worst-case O(n²) recursion. Randomizing the pivot avoids that pattern.

Approach 4: Heap Sort

Intuition: A max-heap keeps the largest value at the root. Swap it to the end, shrink the heap, and restore the heap property. Repeat until the heap has one element.

Key Insights & Pitfalls

Key insight: merge sort's power comes from merging two already-sorted lists. Only the two front elements need comparing, so each merge is linear and each of the log n levels costs O(n).
Pitfall 1: Array.prototype.sort() is forbidden, and the default comparator sorts numbers as strings ([10,2] stays unsorted).
Pitfall 2: shift() is not free. It is O(n); use index pointers in the merge loop.
Pitfall 3: Always append the leftover half after the merge loop, otherwise values disappear.
Pitfall 4: The base case length < 2 is essential; without it, slicing a one-element array recurses forever.
Pitfall 5: Counting sort needs an offset for negative numbers and is only viable when the value range is small.
