Majority Element

LeetCode 169 — Find the value that appears more than half the time

Array Hash Table Sorting Boyer-Moore O(n) O(1) optimal space

Problem Overview

Return the element that appears strictly more than ⌊n / 2⌋ times. The input is guaranteed to contain such an element.

Input: nums = [3,2,3] Output: 3 (3 appears 2 times, and 2 > ⌊3/2⌋ = 1) Input: nums = [2,2,1,1,1,2,2] Output: 2 (2 appears 4 times, and 4 > ⌊7/2⌋ = 3) Input: nums = [1] Output: 1
Key insight: a majority element occupies more than half of all positions, so it must survive any process that cancels pairs of different values.

Approach 1: Brute Force (Count Every Candidate)

Intuition: Try each value as the candidate and scan the entire array to count it. If the count exceeds ⌊n/2⌋, return that value.

Approach 2: Hash Map Counting (Implemented)

Intuition: Count values as they are read. Once a count exceeds half the array, that value is necessarily the majority and can be returned immediately — no other value can catch up.

The map stores {2: 4, 1: 3} at the moment of return. The implementation checks the count before incrementing: previous >= floor(n/2) means the new count is at least floor(n/2) + 1.

const mid = Math.floor(nums.length / 2); const map = new Map(); for (const num of nums) { const occurences = map.get(num) ?? 0; map.set(num, occurences + 1); if (occurences >= mid) return num; }

Approach 3: Sorting

Intuition: After sorting, equal values are contiguous. A value that fills more than half the array must cover the middle index, so the median is the majority element.

Approach 4: Boyer-Moore Voting

Intuition: Pair up different values and cancel them. The majority value has more copies than all other values combined, so it cannot be fully cancelled. A candidate and a count simulate these cancellations in one pass.

The cancellations remove pairs (2,1), (2,1), (1,2), leaving one uncancelled 2. Because 2 is the majority, it is the only possible survivor. If the majority guarantee did not hold, this candidate would need verification.

let candidate = null, count = 0; for (const num of nums) { if (count === 0) candidate = num; count += (num === candidate) ? 1 : -1; } return candidate;

Common Pitfalls

  • Using ≥ n/2 instead of > ⌊n/2⌋. An element occurring exactly n/2 times (for even n) is not a majority.
  • Off-by-one in the early return. The implemented code checks the count before incrementing; previous ≥ floor(n/2) is exactly the right condition.
  • Boyer-Moore without verification. The candidate is guaranteed correct only because a majority exists. Otherwise, a second pass must confirm its count.
  • Adopting a candidate at the wrong time. Reset the candidate only when count === 0, then process the current element.
  • Wrong median index. Use Math.floor(n/2); for n = 7 that is 3, for n = 6 also 3.
  • Using a plain object as a map. Numeric keys are coerced to strings, so distinct values can collide; Map keeps numeric identity.
  • Counting array indexed by value. Values range over −109 to 109; a value-indexed array is impossible.
