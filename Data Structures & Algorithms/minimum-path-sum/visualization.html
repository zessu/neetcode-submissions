Minimum Path Sum

LeetCode 64 — Cheapest top-left to bottom-right path moving only right or down

Array Dynamic Programming Matrix Memoization

Problem Overview

Given an m x n grid of non-negative numbers, find the path from the top-left to the bottom-right that minimizes the sum. Each move goes right or down.

grid = [ [1, 3, 1], [1, 5, 1], [4, 2, 1] ] Optimal path: 1 -> 3 -> 1 -> 1 -> 1 Output: 7

Approach 1: Brute-Force Recursion

Intuition: At each cell, try both legal moves. Recursively compute the best path from each, then add the current cell.

Time: O(2^(m+n)) Space: O(m+n)
Every path has m + n - 2 moves, and each move has two choices
(0,0) = 1 → right: (0,1) down: (1,0)
(0,1) = 3 → right: (0,2) down: (1,1)
(1,0) = 1 → right: (1,1) down: (2,0)

Cell (1,1) is reached from both (0,1) and (1,0). Without memoization, its entire subtree is recomputed.

Approach 2: Memoized DFS (Implemented)

Intuition: The best cost from a cell never changes. Cache it on the first visit and reuse it whenever another path reaches the same cell.

Time: O(m · n) Space: O(m · n) + O(m+n) stack
Recurrence from cell (r, c)
grid[r][c] + min( recurr(r, c+1)  right , recurr(r+1, c)  down )
outside grid → Infinity destination → grid[r][c]
const cache = new Map(); const recurr = (grid, r, c) => { if (r >= rows || c >= columns) return Infinity; if (r === rows - 1 && c === columns - 1) return grid[r][c]; if (cache.has(`${r}:${c}`)) return cache.get(`${r}:${c}`); const right = recurr(grid, r, c + 1); const down = recurr(grid, r + 1, c); const min = Math.min(right, down); cache.set(`${r}:${c}`, min + grid[r][c]); return grid[r][c] + min; };

The key must include both coordinates. Using r + c would treat (1,2) and (2,1) as the same cell.

Approach 3: Bottom-Up DP

Intuition: The best cost to reach a cell is its value plus the smaller of the cell above and the cell to the left. Fill row by row so both are already known.

above = dp[r-1][c] left = dp[r][c-1] → dp[r][c] = grid[r][c] + min(above, left)
dp[0][0] = grid[0][0]; for (let r = 0; r < rows; r++) { for (let c = 0; c < columns; c++) { if (r === 0 && c === 0) continue; if (r === 0) dp[r][c] = dp[r][c - 1] + grid[r][c]; else if (c === 0) dp[r][c] = dp[r - 1][c] + grid[r][c]; else dp[r][c] = grid[r][c] + Math.min(dp[r - 1][c], dp[r][c - 1]); } }

For (1,1), above is 4 and left is 2, so dp[1][1] = 5 + 2 = 7. The final cell is 7.

Only the previous row and the current row are ever needed, so the table can be reduced to a single array of length n. This is the usual production implementation because it cannot overflow the call stack.

Approach 4: In-Place DP

Intuition: Reuse the input grid to store cumulative sums. Each cell is read once before being overwritten, so no extra table is required.

Time: O(m · n) Space: O(1) extra
Mutating the grid in row-major order
first row → add the value to the left
first column → add the value above
any other cell → add min(above, left)

The result is the same 7, but the caller's grid is permanently changed.
